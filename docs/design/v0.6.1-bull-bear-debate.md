# Design — v0.6.1 G1+G6+G17: Bull/Bear Adversarial Debate Stage

**Author:** subagent (delegated design pass)
**Date:** 2026-05-27
**Repo:** `hermes-quant` @ `1c38ee9` (= `e166d8d` on `main`)
**Scope:** TauricResearch parity gaps **G1** (real adversarial Bull/Bear back-and-forth), **G6** (`ResearchPlan` Pydantic standalone classifier), **G17** (conversational, opponent-aware prompts).
**Replaces / supersedes:** the parallel-emit bull/bear loop at `hermes_quant/aggregators/llm_committee.py:689-704` for the **adversarial** path. The deterministic `_build_turns` skeleton in `deliberative.py` is unchanged.

---

## 0. TL;DR for the parent agent

* Promote Bull/Bear from a *parallel pair-emitter* with a counter into a **named pipeline stage** `ResearchDebateStage` that runs **between analyst aggregation and the Trader**, with its own state object `InvestDebateState`, its own env-knob `HERMES_QUANT_RESEARCH_ROUNDS` (default `1`, hard cap `3`), and its own audit `EventKind` `'research_debate'`.
* The stage emits a strongly-typed `ResearchPlan` (G6) that **Trader consumes directly**. `ResearchPlan` already half-exists in `llm_committee.py:87`; we keep the schema, **drop `overrules_baseline`**, **promote `recommendation` to a `PortfolioRating` enum**, and make it the **input contract** of `TraderProposal`.
* Each turn injects the **opponent's last argument verbatim** (`current_response`) plus the **caller's own running history** (`bull_history` / `bear_history`) into a conversational, non-JSON-mandated prompt body. The structured-JSON envelope still wraps the response so the existing `BullBearTurn` validator survives untouched (G17).
* Backward-compat: when `HERMES_QUANT_RESEARCH_ROUNDS` is unset and `max_research_debate_rounds` is `1`, the stage runs **bull → bear → judge** (3 turns), which is *exactly* the current production behaviour. Existing single-turn callers continue to pass.
* The deterministic risk gate (ADR-0004) and the 3-way `RiskCommittee` (ADR-0056) remain **after** the Trader. The TauricResearch order is **Analysts → Research Debate → ResearchManager judge → Trader → Risk Committee**, and we adopt that exact order.

## 1. ADR-0065 — Bull/Bear Adversarial Debate Stage

### Context

`hermes_quant/aggregators/llm_committee.py:689-720` runs the bull and bear roles as a flat for-loop with `consecutive_failures` bail-out:

```python
rounds = max(1, int(config.max_debate_rounds))
for _ in range(rounds):
    for role in _BULL_BEAR_ROLES:           # ← parallel emission
        if not _emit(role) and consecutive_failures >= 2:
            return []
```

Each invocation of `_emit("bull_researcher")` and then `_emit("bear_researcher")` calls `_render_prompt(...)` with the same `prior_turns` list, but the **bull turn at round N does not see the bear turn at round N-1 as the "opponent's most recent argument"** — it just sees a JSON list of all prior turns lumped under `prior_turns_json`. The prompt itself (`bull_bear.md`) is a single-shot structured-JSON template that says nothing about engaging with the opponent.

This diverges from TauricResearch's `InvestDebateState` pattern in three measurable ways:

1. **No alternation contract.** TauricResearch's `ConditionalLogic.should_continue_debate` reads `current_response` and dispatches to whichever side did *not* speak last; we just hard-code `(bull, bear)` per round.
2. **No opponent-anchoring in the prompt.** TauricResearch's bull template literally contains `Last bear argument: {current_response}` and vice-versa. Our `bull_bear.md` lines 37-38 dump *all* prior turns as opaque JSON.
3. **No standalone `ResearchPlan` flowing into Trader.** Today `ResearchPlan` is constructed by `research_manager.md` and stuffed back into the same `committee_turns` extras list. The Trader (`agents/trader.py:115`) does not consume it as a typed input — it reconstructs intent from the aggregated signal.

The 3-way `RiskCommittee` already solved the same shape of problem in `agents/risk_committee/committee.py:_debate_with_llm` (round-robin loop, env-driven `_resolve_max_rounds` clamped to `MAX_ALLOWED_ROUNDS=3`, per-turn audit append, partial-fallback on persona failure). We replicate that pattern for Bull/Bear so that the two adversarial subsystems are operationally identical.

### Decision

Introduce a **new stage** `ResearchDebateStage` (a small module, not a class hierarchy — keep it boring) at `hermes_quant/aggregators/research_debate.py` with:

1. **Pipeline placement: BEFORE Trader, AFTER analyst aggregation, BEFORE risk committee.** The order is:
   ```
   Analysts → BMAAggregator (baseline) → ResearchDebateStage → ResearchManager judge
                                                                       ↓
                                                                 ResearchPlan
                                                                       ↓
                                                                  TraderNode
                                                                       ↓
                                                               TraderProposal
                                                                       ↓
                                                                RiskCommittee
                                                                       ↓
                                                              risk gate (ADR-0004)
   ```
   This matches TauricResearch verbatim. The deterministic `DeliberativeCommitteeAggregator.aggregate(...)` in `deliberative.py:200` keeps producing the BMA baseline as it does today; the LLM debate is now an *append-only* enhancement layer that runs **after** the baseline is computed, and **its output (`ResearchPlan`) is the contract that hands off to Trader.**
2. **State object: `InvestDebateState` Pydantic.** Mirrors TauricResearch's `TypedDict` field-for-field (`bull_history`, `bear_history`, `history`, `current_response`, `count`) plus our own `judge_decision: ResearchPlan | None`. Pydantic, not `TypedDict`, because we already use Pydantic everywhere else in the stack and the audit-log writer expects `.model_dump()`.
3. **Alternation: explicit round-robin.** Turn `2k` is bull, turn `2k+1` is bear. Termination at `count == 2 * max_rounds`. No cleverness via `current_response.startswith("Bull")` — explicit modulo on `count` is auditable and matches `_PERSONA_ORDER[count % 3]` in the risk committee.
4. **Opponent-aware prompt: `bull_bear.md` rewrite.** The new template injects `{current_response}` (opponent's last argument) and `{own_history}` (caller's own running history) and is prefaced with the same `CONVERSATIONAL_PREAMBLE` we use in `risk_committee/personas.py:32`.
5. **`ResearchPlan` Pydantic = the stage's output contract.** Fields:
   * `recommendation: PortfolioRating` (5-tier enum: `Buy`/`Overweight`/`Hold`/`Underweight`/`Sell`).
   * `confidence: float ∈ [0,1]`.
   * `rationale: str` (≤ 6000 chars).
   * `strategic_actions: str` (≤ 4000 chars).
   * `horizon_emphasis: Literal["1d","1w","1M"] | None`.
   * `metadata: dict[str, Any]`.

   We **drop `overrules_baseline`**; the deterministic risk gate is the only authority that can silence a baseline disagreement, and surfacing the bool at this layer encouraged the LLM to lawyer it. The "overrule" relation is computable from `(direction(recommendation), baseline_signal.direction)` at audit time.
6. **`PortfolioRating` enum (5-tier).** The same five labels are present today as a `Literal` in `llm_committee.py:92`; we promote to a real `enum.StrEnum` so it can be imported and matched in tests, in `TraderProposal`, and in audit-log payloads without string drift. (See ADR-0058 / HMM regime classifier for the same StrEnum pattern.)
7. **Knobs.**
   * Env: `HERMES_QUANT_RESEARCH_ROUNDS` (int, default `1`, clamped `[1, 3]`).
   * Config: `DeliberativeConfig.max_research_debate_rounds: int = 1`. The legacy `max_debate_rounds` field is **kept as a deprecated alias** (logs a warning if the new field is unset and the legacy field is non-default) — we do not break v0.5.x callers.
   * Feature flag: `HERMES_QUANT_RESEARCH_DEBATE=1` to opt in. When `0` (default in v0.6.1), `ResearchDebateStage` short-circuits to the legacy `_BULL_BEAR_ROLES` for-loop in `run_llm_committee`. **In v0.6.2 we flip the default to `1` once the test plan below is green.**
8. **Audit trail: new `EventKind = 'research_debate'`.** One `GovernanceEvent` row per stage invocation containing `proposal_id`, `bull_count`, `bear_count`, `terminated_reason ∈ {"max_rounds_reached", "two_consecutive_failures", "exception:<TypeName>", "validation_error"}`, `final_recommendation`, and the `ResearchPlan.model_dump()` payload. **We do not emit one row per turn** — the BullBearTurn objects are already journaled inside `committee_turns` extras. One row per stage keeps audit-log volume bounded (the risk committee chose the opposite tradeoff, one row per persona-turn, because there are only ever 3-9 of those; here the upper bound is 6 turns and we don't need that resolution).

### Consequences

**Positive**
* Closes G1 (real adversarial back-and-forth — verifiable via prompt-hash + opponent-injection unit test).
* Closes G6 (`ResearchPlan` is a typed bridge between research and trading; the Trader's `rationale` field can be derived from `strategic_actions` instead of re-synthesised from the signal).
* Closes G17 (conversational preamble matches the risk committee's, so the audit-time prompt-style is uniform across the codebase).
* Operational uniformity with `RiskCommittee._debate_with_llm` — the on-call engineer who debugged the risk path will recognise the shape.
* Hard cap = 3 rounds = 6 LLM calls of `quick_model` worst-case + 1 `deep_model` judge. At `claude-haiku-4.5` median latency that's ≤ 6 × 1.5s + 1 × 4s ≈ 13s, well inside the existing `request_timeout_s=30.0` per-call budget.

**Negative / risk**
* Adds one Pydantic enum (`PortfolioRating`) and one Pydantic state model (`InvestDebateState`) to the import graph. Mitigation: both live in the new `aggregators/research_debate.py`; nothing else imports them at v0.6.1 except the stage itself, the `bull_bear.md` template renderer, and the test suite.
* The "two consecutive failures → bail" counter now spans bull→bear→bull→bear instead of being reset every pair. Mitigation: that's the *correct* behaviour — two consecutive bad turns is a signal we can't trust the model on this asset/tick regardless of which side failed. Document it in the stage docstring and the test plan covers all-four-failure-positions.
* `overrules_baseline` removal is a json-schema-level breaking change for anyone who had pinned the Pydantic schema in their own tooling. Mitigation: v0.6.1 is a feature release; we ship a `JOURNAL_MIGRATION.md` note (1 paragraph) and the audit-log reader (`governance/audit_log.py:131-145`) is unchanged — old rows still parse because `extra='ignore'` is the historical posture for `GovernanceEvent.payload`.

**Neutral**
* Wave 4 memory injection (`HERMES_QUANT_MEMORY_INJECT=1`, ADR-0042) keeps its **anti-pattern guard**: bull and bear *do not* see lessons; only `research_manager` does. The new stage preserves this — `_render_prompt` already gates on role.

### Alternatives considered

1. **Bull/Bear AFTER risk committee** (i.e. risk gate runs first, debate only on survivors). Rejected. The risk gate is a deterministic cliff and silencing the trade pre-debate would leave us blind to *why* an aggressive sizing was rejected. TauricResearch's order is correct; we follow.
2. **Make `current_response` a list of every prior opponent turn** instead of just the last one. Rejected as a v0.6.1 scope creep — the running `bull_history` / `bear_history` strings already preserve the full chain. The opponent-anchoring point is *recency*, not *completeness*.
3. **Use `langgraph` (TauricResearch's choice) instead of a plain loop.** Rejected. We already chose a plain loop in `RiskCommittee._debate_with_llm`. Operational consistency wins over framework parity.
4. **Use `dataclasses.dataclass(frozen=True)` for `InvestDebateState`.** Rejected because we mutate `count` and append to `bull_history` between turns; a frozen dataclass forces a `dataclasses.replace` per turn that's noisier than `model.bull_history += new_text`. Pydantic with default `model_config = {"frozen": False}` is the right call.
5. **Promote `BullBearTurn` instead of introducing `ResearchPlan` as the Trader hand-off.** Rejected. `BullBearTurn` is a *speech act* (one debater's argument); `ResearchPlan` is a *judgment* (the manager's synthesis). The Trader needs the latter. They're different objects.

### Implementation plan

**Phase 1 — schemas + enum (no behaviour change)**
1. Add `PortfolioRating` `StrEnum` to `hermes_quant/aggregators/research_debate.py`.
2. Add `InvestDebateState` Pydantic to the same module.
3. Move `ResearchPlan` from `llm_committee.py:87` to `research_debate.py`; replace its `recommendation: Literal[...]` with `recommendation: PortfolioRating`; drop `overrules_baseline`. Re-export from `llm_committee` so existing imports still resolve.
4. Add `'research_debate'` to `governance/audit_log.py` `EventKind` Literal AND `VALID_KINDS` tuple.

**Phase 2 — prompt rewrite**
5. Rewrite `aggregators/prompts/bull_bear.md` per §4 below. Add new placeholders `{current_response}`, `{own_history}`, `{round_index}`, `{conversational_preamble}`.
6. Extend `_render_prompt` in `llm_committee.py:234` to populate the new placeholders. When called from the legacy non-staged path the new placeholders fall back to `(none)` strings so the legacy turn shape is bit-identical.

**Phase 3 — stage**
7. Implement `ResearchDebateStage.run(...) -> InvestDebateState` in `aggregators/research_debate.py`. Internally calls `_run_one_turn(role=...)` from `llm_committee.py` (already exists at lines 460-540) twice per round, alternating, then runs the `research_manager` judge once at the end.
8. Add `_resolve_research_max_rounds(explicit) -> int` (cloned shape of `_resolve_max_rounds` from `risk_committee/committee.py:579`).
9. Wire `run_llm_committee` to dispatch to the stage when `HERMES_QUANT_RESEARCH_DEBATE=1`. Otherwise fall through to the existing parallel-emit loop.

**Phase 4 — Trader hand-off**
10. Extend `TraderProposal` with an *optional* `research_plan_id: str | None` and an *optional* `research_plan_recommendation: PortfolioRating | None`. (Strict-typed, backward-compat via `default=None`.) The deterministic v0.1 trader keeps working with both fields `None`; the LLM-trader path (when wired in v0.6.2) will require them.
11. Document in `agents/trader.py` that the v0.1 deterministic node may continue to ignore the `ResearchPlan` — it is a *forward-compat hand-off*, not a *coupling*.

**Phase 5 — audit + flip default**
12. Inside `ResearchDebateStage.run`, append one `GovernanceEvent(kind='research_debate', ...)` per invocation.
13. v0.6.1 ships with `HERMES_QUANT_RESEARCH_DEBATE=0` (opt-in). v0.6.2 flips the default after one observation week of green CI on the staging tick stream.

### Migration

* Code: 100% additive at v0.6.1. The legacy parallel-emit path is preserved behind the feature flag. There is no `git mv` and no rename.
* Audit log: schema unchanged (we add an `EventKind` value, which `EventKind` Literals tolerate via Pydantic's `extra='ignore'` posture for downstream readers; new field `'research_debate'` is rejected by the v0.6.0 reader's `VALID_KINDS` tuple, so v0.6.0 readers must upgrade before they can replay v0.6.1+ rows. Acceptable — audit-log readers are versioned in lockstep with the producer per ADR-0026).
* Configs: `DeliberativeConfig.max_debate_rounds` becomes a *deprecated alias*. Operators are told to switch to `max_research_debate_rounds` and `HERMES_QUANT_RESEARCH_ROUNDS`; both are honored for v0.6.x.

### Test plan

See §7 for the 12+ unit tests. Plus the existing v0.5.1 `tests/integration/test_e2e_pipeline.py` is extended with a new flag-on case that asserts `'research_debate'` rows appear in the journal and that `len(turns_with_role='bull_researcher') == max_rounds`.

## 2. State machine (ASCII)

```
                               ResearchDebateStage.run(...)
                               ─────────────────────────────

   ┌──────────────────┐
   │ init InvestDebate│   bull_history=""  bear_history=""  history=""
   │      State       │   current_response=""  count=0  judge_decision=None
   └────────┬─────────┘
            │
            ▼
       ┌─────────┐
       │ count   │◀─────────────────────────────────────────────┐
       │ < 2*N ? │                                              │
       └────┬────┘   no ──► judge ──► ResearchPlan ──► return  │
            │ yes                                               │
            ▼                                                   │
   ┌──────────────────┐                                         │
   │ count % 2 == 0 ? │                                         │
   └─┬──────────┬─────┘                                         │
     │ yes      │ no                                            │
     ▼          ▼                                               │
  ┌──────┐  ┌──────┐                                            │
  │ BULL │  │ BEAR │                                            │
  │ turn │  │ turn │                                            │
  └──┬───┘  └──┬───┘                                            │
     │         │                                                │
     └────┬────┘                                                │
          ▼                                                     │
   ┌────────────────────────┐                                   │
   │ _run_one_turn(...)     │                                   │
   │  prompt sees:          │                                   │
   │   • current_response   │  ← OPPONENT's last argument       │
   │   • own_history        │  ← caller's own running thread    │
   │   • analyst_views_json │                                   │
   │   • baseline_signal    │                                   │
   └─────┬──────────────┬───┘                                   │
         │              │                                       │
   success│              │None / pydantic-fail                  │
         ▼              ▼                                       │
   ┌──────────┐   ┌─────────────────┐                           │
   │ append   │   │ consecutive++   │                           │
   │ to side- │   │                 │                           │
   │ history; │   │ if ≥ 2:         │                           │
   │ update   │   │   terminated =  │                           │
   │ current_ │   │   "two_consec_  │                           │
   │ response │   │      failures"  │                           │
   │ count++  │   │   break         │                           │
   │ consec=0 │   └─────────────────┘                           │
   └────┬─────┘                                                 │
        │                                                       │
        └───────────────────────────────────────────────────────┘
```

Termination paths:
* `count == 2*N` → `judge` runs → `terminated_reason="max_rounds_reached"` → return `state`.
* `consecutive_failures == 2` → skip remaining turns, **still run judge** with whatever turns we have (mirrors `RiskCommittee._debate_with_llm`'s partial-summary posture) → `terminated_reason="two_consecutive_failures"`.
* Any other exception → caught at outer `try`, `terminated_reason=f"exception:{type(exc).__name__}"`, return whatever we have so far.

## 3. Pydantic schemas

### 3.1 `PortfolioRating` (5-tier StrEnum)

```python
# hermes_quant/aggregators/research_debate.py

import enum

class PortfolioRating(str, enum.Enum):
    """5-tier portfolio rating produced by the ResearchManager judge.

    str-mixin enables json.dumps({"rec": PortfolioRating.BUY}) → {"rec":"Buy"}.
    Order is intentional: index reflects directional intensity from -2 to +2.
    """
    SELL = "Sell"
    UNDERWEIGHT = "Underweight"
    HOLD = "Hold"
    OVERWEIGHT = "Overweight"
    BUY = "Buy"

    @property
    def signed_intensity(self) -> int:
        """Map to a deterministic -2..+2 integer for invariant checks."""
        return {
            PortfolioRating.SELL: -2,
            PortfolioRating.UNDERWEIGHT: -1,
            PortfolioRating.HOLD: 0,
            PortfolioRating.OVERWEIGHT: 1,
            PortfolioRating.BUY: 2,
        }[self]
```

### 3.2 `ResearchPlan` (revised)

```python
class ResearchPlan(BaseModel):
    """Output contract of ResearchDebateStage.

    Replaces the inline Literal in llm_committee.py:87. The prior
    `overrules_baseline: bool` field is REMOVED — the deterministic risk gate
    (ADR-0004) is the only authority for direction-vs-baseline disputes;
    surfacing a bool at this layer encouraged the LLM to lawyer it.
    """
    model_config = {"extra": "forbid", "str_strip_whitespace": True}

    recommendation: PortfolioRating
    confidence: float = Field(..., ge=0.0, le=1.0)
    rationale: str = Field(..., min_length=1, max_length=6000)
    strategic_actions: str = Field(..., min_length=1, max_length=4000)
    horizon_emphasis: Literal["1d", "1w", "1M"] | None = None
    metadata: dict[str, Any] = Field(default_factory=dict)
```

### 3.3 `InvestDebateState` (new)

```python
class InvestDebateState(BaseModel):
    """Mirrors TauricResearch InvestDebateState (TypedDict) as a Pydantic model.

    Mutated in-place across turns by ResearchDebateStage.run. After the stage
    completes, the model is .model_dump()ed into the audit log.
    """
    model_config = {"extra": "forbid", "validate_assignment": True}

    bull_history: str = ""
    bear_history: str = ""
    history: str = ""
    current_response: str = ""
    judge_decision: ResearchPlan | None = None
    count: int = Field(default=0, ge=0)
    # Hermes-only (not in TauricResearch): per-turn structured records so the
    # journal does not lose the per-side confidence floats.
    bull_turns: list[BullBearTurn] = Field(default_factory=list)
    bear_turns: list[BullBearTurn] = Field(default_factory=list)
    # Termination metadata (Hermes-only).
    terminated_reason: Literal[
        "max_rounds_reached",
        "two_consecutive_failures",
        "validation_error",
    ] | str = "max_rounds_reached"  # str fallback for "exception:<Type>"
```

### 3.4 Updated `TraderProposal` (additive only)

## 4. Prompt diff: `aggregators/prompts/bull_bear.md`

### Current (v0.5.1, 40 lines, structured-JSON only)

```
SYSTEM:
You are the {role_label} on a trading-research committee evaluating {asset}
({asset_class}) over the {horizon} horizon. Your job is to make the strongest
possible {role_direction} case using ONLY the evidence provided below. ...

Output a single JSON object matching this schema (no prose outside JSON):
{{
  "role": "{role_value}",
  "stance": "<one-line summary of your position>",
  ...
}}

USER:
Asset: {asset} ({asset_class}, {horizon})
...
Prior committee turns (if any) for cross-engagement:
{prior_turns_json}
```

### Proposed (v0.6.1, conversational, opponent-aware)

```
SYSTEM:
You are the {role_label} on a trading-research committee evaluating {asset}
({asset_class}) over the {horizon} horizon. This is round {round_index} of an
adversarial debate against the opposing analyst. Your job is to make the
strongest possible {role_direction} case using ONLY the evidence provided
below, and to **engage directly with the opposing analyst's most recent
argument** — quote it, dispute it, refine your position in light of it.

{conversational_preamble}, presenting your arguments as if you were directly
speaking to the opposing analyst at the round-robin debate. Engage with their
points by name, defend your high-conviction stance, and make a compelling
case for why your direction is the right one — but if their argument lands,
say so and update your confidence downward. Manufactured certainty in the
face of a strong opponent argument is a worse failure than abstention.

Silence-by-default rule (mandatory): if the analyst evidence is weak,
contradictory, or insufficient to support a {role_direction} case, return
confidence < 0.5 and say so explicitly in `rationale`.

Mirror-image rule: in `counterarguments`, faithfully steelman the OTHER side's
strongest objection — including the one they just made.

Despite the conversational framing, your final response MUST still be a single
JSON object matching this schema (no prose outside JSON). Put the conversational
content inside `rationale`:
{{
  "role": "{role_value}",
  "stance": "<one-line summary of your position>",
  "confidence": <float 0.0-1.0>,
  "rationale": "<<= 500 words conversational narrative engaging the opponent>",
  "key_evidence": ["<analyst name or fact>", ...],
  "counterarguments": "<steelman of the opposing analyst's argument>",
  "metadata": {{"tier": "quick", "round": {round_index}}}
}}

USER:
Asset: {asset} ({asset_class}, {horizon})
Decision timestamp (UTC): {asof}

Baseline BMA aggregator output (deterministic):
{baseline_signal_json}

Analyst views ({n_views} total, calibrated):
{analyst_views_json}

Your own running thread so far (you said this; don't contradict yourself
without explanation):
{own_history}

The opposing analyst just said this — engage with it directly:
---
{current_response}
---

Produce your {role_direction} case as a single JSON object per the schema.
```

**Key changes:**
* New placeholders: `{round_index}`, `{conversational_preamble}`, `{own_history}`, `{current_response}`.
* Drops `prior_turns_json` (the opaque blob is replaced by the two scoped strings above).
* Adds the verbatim TauricResearch conversational framing (G17).
* Keeps the JSON envelope so `BullBearTurn` Pydantic validation continues to work — *the rationale is conversational text inside a structured envelope*. We get the best of both: human-style argument quality, machine-style audit shape.
* On round 1 turn 0 (the very first bull turn), `own_history=""` and `current_response="(no prior turn — open the debate)"`. The prompt gracefully degrades.

## 5. Pseudo-code: alternating loop

(Modeled on `RiskCommittee._debate_with_llm` at `risk_committee/committee.py:297-377` and `_resolve_max_rounds` at `:579-598`.)

```python
# hermes_quant/aggregators/research_debate.py

DEFAULT_MAX_RESEARCH_ROUNDS: int = 1
MAX_ALLOWED_RESEARCH_ROUNDS: int = 3
RESEARCH_ROUNDS_ENV_VAR: str = "HERMES_QUANT_RESEARCH_ROUNDS"
RESEARCH_DEBATE_FLAG_ENV_VAR: str = "HERMES_QUANT_RESEARCH_DEBATE"
_RESEARCH_DEBATE_AUDIT_KIND: str = "research_debate"

CONVERSATIONAL_PREAMBLE: str = (
    # Imported verbatim from agents/risk_committee/personas.py:32 to keep
    # the two adversarial subsystems' style identical (G17 uniformity).
    "Output conversationally as if you are speaking without any special "
    "formatting"
)


def _resolve_research_max_rounds(explicit: int | None) -> int:
    """Mirror of RiskCommittee._resolve_max_rounds for the research stage."""
    if explicit is not None:
        n = int(explicit)
    else:
        raw = os.environ.get(RESEARCH_ROUNDS_ENV_VAR)
        if not raw:
            n = DEFAULT_MAX_RESEARCH_ROUNDS
        else:
            try:
                n = int(raw)
            except (TypeError, ValueError):
                logger.warning(
                    "%s=%r is not an int; falling back to default %d",
                    RESEARCH_ROUNDS_ENV_VAR, raw, DEFAULT_MAX_RESEARCH_ROUNDS,
                )
                n = DEFAULT_MAX_RESEARCH_ROUNDS
    return max(1, min(MAX_ALLOWED_RESEARCH_ROUNDS, n))


def run_research_debate(
    *,
    market_context: MarketContext,
    analyst_views: list[AnalystView],
    baseline_signal: AggregatedSignal,
    config: DeliberativeConfig,
    client: Any,
    max_rounds: int | None = None,
    proposal_id: str | None = None,
) -> InvestDebateState:
    """Run the bull/bear adversarial stage and return the final state.

    Failure-closed (mirrors run_llm_committee at llm_committee.py:625):
      * Two consecutive turn failures → break, judge with what we have.
      * Any uncaught exception → caught at outer try, terminated_reason
        records the exception type, return partial state.

    The judge (research_manager) is run AT THE END of the loop with
    state.bull_turns + state.bear_turns as its prior_turns input. It
    populates state.judge_decision: ResearchPlan.
    """
    rounds = _resolve_research_max_rounds(max_rounds)
    pid = proposal_id or f"rdp-{uuid.uuid4().hex[:12]}"
    state = InvestDebateState()
    consecutive_failures = 0

    try:
        max_turns = 2 * rounds
        while state.count < max_turns:
            is_bull = (state.count % 2 == 0)
            role = "bull_researcher" if is_bull else "bear_researcher"
            own_history = state.bull_history if is_bull else state.bear_history

            turn = _run_one_turn_with_history(
                role=role,
                client=client,
                config=config,
                market_context=market_context,
                analyst_views=analyst_views,
                baseline_signal=baseline_signal,
                # NEW: opponent-anchoring parameters
                current_response=state.current_response or
                                 "(no prior turn — open the debate)",
                own_history=own_history or "(no prior turns by you yet)",
                round_index=(state.count // 2) + 1,
                conversational_preamble=CONVERSATIONAL_PREAMBLE,
            )

            if turn is None:
                consecutive_failures += 1
                if consecutive_failures >= 2:
                    state.terminated_reason = "two_consecutive_failures"
                    break
                # Skip this turn but advance count so we don't infinite-loop on
                # the same role. Cost: opponent doesn't get a fresh
                # current_response this iter; on retry we'll inject the
                # last successful one. This matches risk-committee semantics.
                state.count += 1
                continue

            consecutive_failures = 0
            structured = BullBearTurn.model_validate(turn.metadata["structured"])
            speech = structured.rationale
            if is_bull:
                state.bull_turns.append(structured)
                state.bull_history += f"\n[Bull r{state.count//2 + 1}] {speech}"
            else:
                state.bear_turns.append(structured)
                state.bear_history += f"\n[Bear r{state.count//2 + 1}] {speech}"
            state.history += f"\n[{role} t{state.count}] {speech}"
            state.current_response = (
                ("Bull: " if is_bull else "Bear: ") + speech
            )
            state.count += 1

    except Exception as exc:  # noqa: BLE001 — failure-closed at top
        logger.warning(
            "ResearchDebateStage aborted (%s) after %d turns; "
            "running judge on partial state.",
            exc, state.count, exc_info=True,
        )
        state.terminated_reason = f"exception:{type(exc).__name__}"

    # Always attempt the judge, even on partial state. The deep-tier judge
    # already has its own try/except + Pydantic validator inside _run_one_turn.
    state.judge_decision = _run_research_manager_judge(
        client=client, config=config,
        market_context=market_context,
        analyst_views=analyst_views,
        baseline_signal=baseline_signal,
        bull_turns=state.bull_turns,
        bear_turns=state.bear_turns,
    )

    # Audit append — exactly one row per stage invocation.
    _audit_append(
        kind=_RESEARCH_DEBATE_AUDIT_KIND,
        source="hermes_quant.aggregators.research_debate",
        payload={
            "proposal_id": pid,
            "asset": market_context.asset,
            "asof": str(market_context.asof),
            "rounds_configured": rounds,
            "bull_count": len(state.bull_turns),
            "bear_count": len(state.bear_turns),
            "terminated_reason": state.terminated_reason,
            "final_recommendation": (
                state.judge_decision.recommendation.value
                if state.judge_decision else None
            ),
            "research_plan": (
                state.judge_decision.model_dump() if state.judge_decision else None
            ),
        },
    )
    return state
```

## 8. Open questions for the parent agent / reviewer

1. **Should `ResearchDebateStage` short-circuit to BMA-only when `len(analyst_views) < 2`?** The `DeliberativeCommitteeAggregator.aggregate(...)` already handles this case via `_flat_from_baseline(..., "insufficient_effective_views")` at `deliberative.py:209`. Recommendation: yes, mirror that posture — return an `InvestDebateState` with `terminated_reason="insufficient_views"`, `count=0`, `judge_decision=None`. Add as test T15 if accepted.
2. **Does the v0.6.1 release plan permit the audit-log `EventKind` Literal expansion as a non-breaking change?** ADR-0026 says yes (readers version in lockstep with producers); reviewer may want to confirm.
3. **Risk-committee parity question:** the risk committee emits one audit row *per persona turn*. We chose one *per stage*. If the reviewer prefers per-turn for symmetry, swap §6 implementation to a `for turn in (state.bull_turns + state.bear_turns): _audit_append(...)` loop. Test T9 expectation flips to `n_rows == bull_count + bear_count + 1` (the extra is the judge). Either is defensible; per-stage keeps audit volume bounded for the (longer) Bull/Bear path.
