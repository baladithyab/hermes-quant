Do **not** add `arch` or `statsmodels` as a dependency (neither is installed in `~/.hermes/hermes-agent/venv`). The stationary-bootstrap + Politis-White optimal block length is ~60 LOC of numpy and was prototyped + validated during this research (see §4). `scipy` is already an optional extra (`pyproject.toml` `[stacking]`/`[options]`) and the repo's `_HAS_SCIPY` fail-closed pattern (`hermes_quant/factors/ic_metrics.py:36-40`) is the precedent to reuse for the BCa path.

## 1. Decisive external findings (with sources)

### 1.1 Probabilistic / Deflated Sharpe Ratio — already correct in the repo
- Bailey & López de Prado (2014), "The Deflated Sharpe Ratio: Correcting for Selection Bias, Backtest Overfitting, and Non-Normality", JPM 40(5):94-107. PDF: https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf ; SSRN: https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2465675
- Bailey & López de Prado (2012), "The Sharpe Ratio Efficient Frontier" (PSR): https://www.davidhbailey.com/dhbpapers/sharpe-frontier.pdf
- PSR formula (ml4trading.io primer, Quantdare): `PSR(SR0) = Φ[ (SR_hat − SR0)·sqrt(T−1) / sqrt(1 − γ3·SR_hat + ((γ4−1)/4)·SR_hat²) ]`, where γ4 is the (non-excess) kurtosis (=3 for normal). **This is exactly what `hermes_quant/evaluation/dsr.py:deflated_sharpe()` already computes** (it matches the `variance_term = 1 − skew·SR + (kurtosis−1)/4·SR²` line and the `sqrt(n−1)` numerator). The DSR hurdle `SR0 = E[max{SR_n}]` for n_trials>1 is also already implemented via the Euler-Mascheroni expansion. **Do not reimplement — call it.**
- Caveat from the primer (https://ml4trading.io/primer/deflated-sharpe-ratio-and-search-aware-backtest-inference/): PSR/DSR assumes returns are *IID* (non-normal allowed but serially independent). Autocorrelated returns violate this — which is precisely why the **bootstrap CI must be a block bootstrap**, and why these two methods (DSR vs block-bootstrap CI) are complementary, not redundant.

### 1.2 Stationary / circular block bootstrap for autocorrelated returns
- Politis & Romano (1994), "The Stationary Bootstrap", JASA 89:1303-1313 — the stationary bootstrap (SB): blocks of random (geometric, mean = b) length, wraps circularly, produces a stationary resampled series. Preferred over moving-block because the resample is itself stationary and SB is *less sensitive to block-size misspecification* (Politis & White 2004, §3.1).
- **Optimal expected block length**: Politis & White (2004), "Automatic Block-Length Selection for the Dependent Bootstrap", Econometric Reviews 23(1):53-70, https://public.econ.duke.edu/~ap172/Politis_White_2004.pdf — the flat-top-lag-window spectral plug-in (PWSD method). **Corrected** by Patton, Politis & White (2009), Econometric Reviews 28(4):372-375, https://public.econ.duke.edu/~ap172/SBblockCORRECTION_jan08.pdf — the key correction is `D_SB = 2·g²(0)` (was wrong in the 2004 paper).
- Canonical Python reference (NOT installed, but the algorithm spec is the authority): `arch.bootstrap.optimal_block_length` and `arch.bootstrap.StationaryBootstrap` (https://arch.readthedocs.io/en/stable/bootstrap/generated/arch.bootstrap.optimal_block_length.html ; bootstrap_examples). The arch doc gives the exact, implementable formula:
  - tuning `m` = first lag where `k_n` consecutive autocorrelations all fall inside `±2·sqrt(log10(n)/n)`, with `k_n = max(5, log10(n))`, `m_max = ceil(sqrt(n)) + k_n`;
  - `M = 2·m`; flat-top kernel `h(x) = min(1, 2(1−|x|))`;
  - `g = Σ_{k=−M..M} h(k/M)·|k|·γ_k`; `σ̂² = Σ h(k/M)·γ_k`; `d_SB = 2·(σ̂²)²` (the 2009 correction; arch uses `c_i=2` for SB, `4/3` for circular);
  - `b_opt = (2·g² / d_SB · n)^(1/3)`, capped at `b_max = ceil(min(3·sqrt(n), n/3))`.
- The arch example explicitly notes: for the Sharpe ratio, run `optimal_block_length` on the **squared returns** because "the Sharpe ratio depends on the mean and the variance, and the autocorrelation in the squares is stronger than in the returns." We adopt this: compute block length on `r**2` (or on a small grid and take the max), then resample the *return level* series with that block length.
- R cross-check: `blocklength::pwsd` (https://alec-stashevsky.github.io/blocklength/) gives `b_Stationary ≈ 8-11` on an AR(1) with ρ≈0.5-0.55 — **our numpy prototype returned 10.58 for AR(1) ρ=0.5 and 1.0 for IID noise** (see §4). Match confirmed.

### 1.3 Monte-Carlo permutation test for trade-sequence significance
- Timothy Masters, "Permutation and Randomization Tests for Trading System Development" (2020), and the public Monte-Carlo doc https://www.evidencebasedta.com/montedoc12.15.06.pdf — the canonical "position↔return pairing is random" null. Procedure: compute candidate net return; repeatedly **shuffle the per-bar return sequence (Fisher-Yates)** while holding the position/weight vector fixed; recompute the statistic; `p = #{perm_stat ≥ obs_stat} / n` (with the conservative `(1+·)/(M+1)` correction).
- quantpylib "Statistical Finance" (https://quantpylib.hangukquant.com/learn/statistical_finance/) formalizes two distinct nulls and the **exact Laplace-smoothed estimator the repo already uses**:
  `p̂ = (1 + Σ_{i=1..M} 1{ψ^(i) ≥ ψ_obs}) / (M + 1)`
  - **OOS asset-timing-skill test**: permute the *time index* of the realized return series while keeping weights fixed → isolates timing skill from static exposure / market drift. This is the right null for hermes-quant's realized paper-book per-bar return series.
  - In-sample-overfit test (re-run the strategy on permuted bars) requires re-running the engine on each permutation; out of scope for v1 (heavy + needs the strategy callable). v1 permutes the *already-realized* return series only → cheap, deterministic, no engine re-run, no lookahead surface.
- Masters tie-breaking caveat (evidencebasedta doc): sign-only statistics produce many ties and an artificially conservative p-value. Mitigation: use the continuous return magnitude (not sign) as the statistic, which our Sharpe/total-return statistics already do.

### 1.4 scipy.stats.bootstrap — verified in-venv (scipy 1.17.1)
- https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html
- Signature `bootstrap(data, statistic, *, n_resamples=9999, method='BCa', confidence_level=0.95, alternative='two-sided'|'greater', paired=False, rng=..., vectorized=...)`.
- **Verified deterministic** with seeded `rng=np.random.default_rng(seed)` (two runs byte-identical, §4). `alternative='greater'` yields a one-sided lower bound at the equivalent confidence (ADR-0029's "use the LOWER bound" gate).
- **LIMITATION (decisive):** `scipy.stats.bootstrap` does plain IID resampling — it *destroys* serial dependence. It is acceptable for the ADR-0029 daily-paper-book promotion gate (daily strategy returns ≈ weakly autocorrelated) but is **not** the correct tool for the autocorrelated-returns requirement in B32. Therefore the validation module's *primary* CI is the **stationary block bootstrap** (our numpy impl); scipy BCa on the IID-resampled series is emitted as a *secondary* CI for cross-reference and as the graceful path when scipy is present. When scipy is absent, fall back to a percentile CI from the stationary-bootstrap distribution (no scipy needed).

## 3. Recommended implementation for THIS repo

### 3.1 New module: `hermes_quant/evaluation/validation.py` (pure, no I/O, deterministic)

Public API (frozen dataclasses + one entry function), mirroring the dsr.py / lookahead.py style:

```
@dataclass(frozen=True)
class BootstrapCI:
    statistic: str            # "sharpe" | "excess_return"
    point: float
    ci_low: float             # 2-sided low  (also the 1-sided lower at same level)
    ci_high: float
    confidence_level: float   # 0.95
    n_resamples: int          # e.g. 9999
    block_length: float       # Politis-White expected block length (1.0 == IID)
    method: str               # "stationary_block" | "bca_iid" | "percentile_iid"

@dataclass(frozen=True)
class PermutationResult:
    statistic: str            # "sharpe" | "total_return" | "excess_return"
    observed: float
    p_value: float            # (1 + #{perm >= obs}) / (M + 1)   one-sided right tail
    n_permutations: int
    perm_mean: float
    perm_std: float
    alpha: float

@dataclass(frozen=True)
class ValidationReport:
    seed: int
    n_observations: int
    bars_per_year: float
    deflated_sharpe: float            # from evaluation.dsr.deflated_sharpe
    permutation: list[PermutationResult]
    bootstrap: list[BootstrapCI]
    walk_forward: dict | None         # positive_excess_fold_rate, mean_sharpe_delta, n_splits
    warnings: list[str]
    def to_dict(self) -> dict: ...    # sort_keys-friendly, json-serializable

def validate_returns(
    strat_returns: "pd.Series | np.ndarray",
    *,
    bars_per_year: float,
    bh_returns=None,                  # optional, enables excess-return stats
    n_permutations: int = 1000,
    n_resamples: int = 9999,
    confidence_level: float = 0.95,
    alpha: float = 0.05,
    seed: int = 42,
    walk_forward_summary: dict | None = None,
) -> ValidationReport: ...
```

Internal helpers (numpy-only, validated in §4):
- `_politis_white_block_length(x) -> float` — PWSD plug-in with the Patton-2009 `D_SB = 2g²(0)` correction; run on `x**2` for the Sharpe statistic; clamp to `[1, ceil(min(3*sqrt(n), n/3))]`.
- `_stationary_bootstrap_indices(n, b, n_resamples, rng) -> np.ndarray[(n_resamples, n)]` — geometric-length wrapping blocks, `p = 1/b`; **single shared seeded `rng`** for full determinism.
- `_permutation_pvalue(returns, statistic_fn, n_permutations, rng)` — Fisher-Yates shuffle of the realized return sequence (timing-skill null), `(1 + count)/(M+1)`; mirror `lookahead.py`.
- Reuse `replay._sharpe` annualization (import or duplicate the 6-line helper to avoid a circular import — prefer a tiny local copy with a comment pointing at `replay._sharpe` as source of truth, since `evaluation/` must not depend on `backtest/`).

Determinism rule: derive sub-seeds from the single `seed` (e.g. `rng = np.random.default_rng(seed)`; spawn `rng.spawn(2)` for permutation vs bootstrap) so the whole report is one-seed reproducible.

## 6. Pitfalls + rails to respect

**No-lookahead**
- The validation suite operates on an **already-realized, fixed** per-bar return series produced by the no-lookahead `replay`/`walk_forward_replay` path. It never re-runs the strategy on resampled bars (which would risk re-introducing lookahead). Resampling a fixed outcome vector cannot create lookahead.
- Walk-forward concatenation: only concatenate **OOS test-fold** returns (folds are non-overlapping; `cv.py` `assert_no_leakage` already guarantees `val_end <= test_start`). Preserve chronological fold order; do not interleave folds.
- The MC permutation uses the *timing-skill* null (shuffle realized return sequence, hold weights fixed) per quantpylib — it tests temporal structure, consistent with the existing `lookahead.py` philosophy.

**Determinism**
- Single integer `seed` (default 42, matching `lookahead.py`) → one `np.random.default_rng(seed)`; derive independent streams via `rng.spawn(...)`. scipy bootstrap gets `rng=np.random.default_rng(child_seed)`. Verified byte-identical across runs (§4).
- `validation.json` written with `json.dumps(..., indent=2, sort_keys=True, default=str)` (house convention). `generated_at`/`run_at` is the only non-deterministic field — keep it out of any hash; reuse `result.config_hash` for reproducibility pinning.

**Silence-by-default / default-OFF**
- New `--validate` CLI flag defaults to **False**. No cron, no daemon path, no auto-emission. The module is import-only until explicitly invoked. It produces *evidence*, never a trade or a promotion — the deterministic risk gate / promotion machinery (ADR-0004, ADR-0029) remains the final authority; `validation.json` is an *input* to that gate (the CI **lower bound** field), not a decision.

**Fail-closed**
- scipy absent → emit `percentile` CI from the stationary-bootstrap distribution + a `warnings[]` entry; never crash, never silently claim a BCa CI.
- `n_observations < 30` → DSR returns NaN (its own guard, `dsr.py:56`); validation flags low power in `warnings[]` and still emits permutation/bootstrap (with a power caveat) rather than throwing.
- Degenerate series (zero variance, all-identical) → BCa can emit NaN (scipy `DegenerateDataWarning`); catch and downgrade to percentile, flag in warnings. Mirror `replay.py:503` `except (ValueError, ZeroDivisionError)`.
- Block length is clamped to `[1, ceil(min(3·sqrt(n), n/3))]`; `b==1` degrades gracefully to an IID bootstrap (correct behavior for serially-independent returns).

**Statistical correctness traps**
- Run Politis-White on **squared returns** for the Sharpe CI (arch guidance: variance autocorrelation dominates). Take `max(block_length(r), block_length(r**2))` to be conservative.
- Use the **continuous** return magnitude as the permutation statistic, not sign-only (Masters: sign-only inflates ties → anti-conservative/over-conservative p). Apply `(1 + count)/(M + 1)` Laplace smoothing (already the `lookahead.py` convention).
- DSR (IID assumption) and the block-bootstrap CI (handles autocorrelation) are **complementary** — report both; do not treat DSR as a substitute for the CI when returns are autocorrelated.
- One-sided lower bound for the gate input: scipy `alternative='greater'` (lower bound at the equivalent level) per ADR-0029.

## 7. Scope decision (explicit)

**BUILD.** Rationale: (1) the artifact (`validation.json`) and the method (BCa bootstrap CI lower-bound, shuffle/permutation null, walk-forward) are *already specified* across ADR-0029, ADR-0003, ADR-0006 and the Vibe-Trading R3 schema note — B32 is the missing plumbing, not new research; (2) it extends, not duplicates, the existing `evaluation/dsr.py` + `cv.py` + `walk_forward.py` machinery (calls `deflated_sharpe`, consumes `WalkForwardBacktestResult`); (3) it is implementable with **zero new dependencies** (stdlib+numpy primary, scipy optional via the established `_HAS_SCIPY` fallback) — proven deterministic in-venv during this research; (4) it is purely additive, default-OFF, fail-closed, and produces evidence consumed by (never overriding) the deterministic gate, fully consistent with the money-software posture. Estimated size: M (one ~250-LOC module + ~30-LOC CLI wiring + tests + a short ADR amendment).
