# AI-Trader Pattern Extraction for Hermes-Quant

## 1. Agent Skill Registry Shape

**File path:** `skills/*/SKILL.md` (e.g. `skills/ai4trade/SKILL.md`, `skills/copytrade/SKILL.md`)

**Pattern:** AI-Trader uses Markdown files with YAML frontmatter as its skill registry. Agents download a `.md` file containing API endpoints, authentication guides, schemas, and descriptions. OpenClaw plugins are mapped to these URLs.

**Comparison to hermes-quant:**
- **AI-Trader:** Registry is network-hosted URL (e.g., `https://ai4trade.ai/skill/ai4trade`), completely decoupled. The Markdown format defines natural-language instructions (prompt injection) telling the LLM how to call the endpoints.
- **hermes-quant:** Uses `recipes.py` `PDRRecipe`. Skills are statically defined Python classes or strict plugins via manifest (`plugin.yaml`).
- **Takeaway:** AI-Trader's prompt-injected Markdown is excellent for unstructured LLM platforms (OpenClaw, Cursor) but dangerous for a purely deterministic trading gateway because the parsing of "how to trade" is left to the LLM. 

## 2. Signal Publishing Protocol

**File path:** `service/server/routes_signals.py` & `service/server/database.py` (Table `signals`)

**What is a signal?**
A signal is an HTTP POST payload containing an action, symbol, price, quantity, and text content. In the database, it's stored in the `signals` table with `message_type` ('strategy', 'operation', 'discussion') and `market`.

**Schema/Transport:**
Agents POST to `/api/signals/realtime`.
```json
{
    "action": "buy",
    "symbol": "BTC",
    "price": 51000,
    "quantity": 0.1,
    "content": "Adding position"
}
```
*Note: AI-Trader is entirely an HTTP REST pull/push system for signals rather than a message queue or append-only file bus.*

**Flow:**
Analyst (Agent A) POSTs to `/api/signals/realtime` -> backend creates `signals` row -> loops over subscriptions -> auto-creates `positions` row for copying.

## 3. Copy-Trading Mechanics

**File paths:** `service/server/routes_trading.py` (Follow/Unfollow), `service/server/services.py` (`_update_position_from_signal`)

**Mechanics:**
Agent B calls `/api/signals/follow` with `leader_id`. The backend creates a `subscriptions` row.
When Agent A posts a signal, the system intercepts it in `_update_position_from_signal` and cascades the position to all followers.

**Fund Movement & Risk:**
The position is copied **1:1 automatically**. 
**Crucial Anti-Pattern:** When an agent subscribes to a leader, *all future trades by that leader are automatically executed against the follower's simulated balance without confirmation.* Although this is paper trading in AI-Trader, mapping this blindly to real money is a catastrophic posture violation for hermes-quant. We must NEVER automatically side-effect real balances based on third-party API calls without explicit CLI confirmation.

## 4. Broker Sync Layer

**Adapter Interface:**
AI-Trader does *not* seem to have a strict programmatic adapter interface for real brokers in this snapshot; it primarily models everything in its internal SQLite database `positions` and `agents` tables via paper cash. It relies on the agents themselves using their *own* tools to sync real trades into AI-Trader via `/api/signals/realtime` (tradesync). It acts as the aggregator, not the execution gateway.

**Comparison to hermes-quant:**
- **AI-Trader:** Leaves broker execution entirely to the agent's side. AI-Trader just asks the agent to "tell me what you did."
- **hermes-quant:** Owns the `ccxt`/`alpaca` DataProvider / `req_order` path natively and runs defensively.

## 5. Paper-Trading Fidelity

**Level:** **L0 Synthetic / L1 Quote-Aware**
When a signal comes in, it accepts the price provided by the agent or fetches a reference price if `should_fetch_server_trade_price` is true (e.g., Polymarket token resolution). It does not appear to model queue position, latency, slippage, or complex order types (limit, stop). `_update_position_from_signal` simply updates average entry price and quantity mathematically (`current_qty + quantity`, entry price blended).

## 6. Permissioning

**File path:** `service/server/routes_models.py`, `service/server/routes_signals.py`
Auth is managed via a JWT-like bare string token in the `Authorization: Bearer <token>` header (`_extract_token`).
- **Publish Signals:** Any registered agent with a token can hit `/api/signals/realtime`.
- **Subscribe/Copy:** Any registered agent can hit `/api/signals/follow`.
- There are no capability scopes; the token is a god-key for that agent ID. 

## 7. 3 Specific Patterns to STEAL

1. **Market Context Tagging (Polymarket Support):** 
   `token_id` and `outcome`. The concept of tagging a signal not just with a ticker string but with a specific market/outcome resolution ID is strong for prediction markets. (`database.py` schema for signals)
2. **Signal Types Separation:**
   `message_type` being split into `operation` (executed trade), `strategy` (idea/thesis), and `discussion`. hermes-quant currently conflates `AnalystView` with execution signals. Having a separate 'thesis' bus is valuable.
3. **Follower Leaderboards (Internal Evaluation):**
   AI-Trader scores agents internally. We should steal the leaderboard concept for our local RL evaluation to rank algorithms offline. 

## 8. 3 Specific Anti-Patterns to AVOID

1. **Token God-Keys without Capability Scopes:** 
   An API token in AI-Trader can both read signals AND place copy-trades. In hermes-quant, plugin read tools and execution channels must remain strictly segregated.
2. **1:1 Blind Copy-Trading:**
   `_update_position_from_signal` blindly mirroring `leader_id` trades without sizing controls or margin checks relative to the follower's NAV.
3. **Continuous/Agent-Submitted Pricing:**
   Accepting `price: 51000` via JSON from the agent payload. Our daemon must dictate fill pricing locally from the data provider, not trust the agent's hallucinations of the price.

## 9. ADR Recommendations

**Recommend a NEW ADR: ADR-0009: Peer Signal Ingestion.**
If we plan to ingest third-party signals (like AI-Trader's marketplace) into hermes-quant, it cannot route directly to execution. Instead, external signals must be treated as `DataProvider` inputs or a special `ExternalAnalyst` stream. The BMA/Aggregator (ADR-0003) must gate and aggregate these peer signals just like internal MACD signals, subject to the Risk Gate (ADR-0004).
