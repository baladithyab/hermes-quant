**Verdict:** **FOLD_INTO_OTHER** — keep the deterministic trim, replace the *misattributed* 5-layer TODO with a correctly-scoped deterministic compaction (Layer-0 microcompact + a deterministic info-theoretic row-keep), drop the two LLM layers entirely. Do **not** build the "full HKUDS 5-layer pipeline" as written in the TODO.

## 1. Decisive external findings

### 1.1 The "5 layers" in the TODO are a misattribution (the load-bearing finding)

The TODO at `data_grounding.py:19` and `:313` lists:
> Layer 0 microcompact float repr / Layer 1 per-window **LLM** summary / Layer 2 iterative context update / Layer 3 semantic dedup / Layer 4 information-theoretic truncation

DeepWiki on **HKUDS/Vibe-Trading** (https://deepwiki.com/HKUDS/Vibe-Trading) confirms these five names are **NOT** a market-data compression scheme. They are Vibe-Trading's *conversation/agent-loop* context-management layers in `agent/src/agent/loop.py`:

- Layer 1 `microcompact` — silently prunes old tool results (deterministic).
- Layer 2 `context_collapse` — folds long text blocks, **no LLM** (deterministic).
- Layer 3 `auto_compact` — **uses an LLM** for structured summarization with tail protection.
- Layer 4 `compact tool` — model explicitly calls a compact tool → triggers Layer 3 (**LLM decision**).
- Layer 5 `iterative update` — updates the previous summary instead of regenerating (**uses an LLM**, `_ITERATIVE_UPDATE_PROMPT`).

So three of the five canonical layers **require an LLM call**. Porting them verbatim into `data_grounding` would directly violate B46's own no-LLM / determinism / silence contract.

The thing this repo actually ported — the **Data Grounding Block** — lives in Vibe-Trading's `agent/src/swarm/grounding.py` and is *fully deterministic, no LLM*. DeepWiki (search `cd9f7d04` / `7d8054c4`) confirms its real design:
- `format_grounding_block` renders a markdown table with **Date / Close / Volume** only.
- `PROMPT_TABLE_TAIL = 5` → renders only the **most recent 5 rows** per symbol.
- Window summary = `last_close`, `window_low = min(closes)`, `window_high = max(closes)` over the full window; all prices `:.2f`, volume as comma-int.
- **No byte/token cap** inside `format_grounding_block`; size is bounded indirectly by `DEFAULT_MAX_SYMBOLS=8` and the 5-row tail.
- Test fixture: `agent/tests/test_swarm_grounding.py::test_format_renders_table_and_range`.

Implication: HKUDS's own grounding block is *simpler* than hermes-quant's current v0.1 (5 recent rows + min/max range, no weekly backfill). The repo's v0.1 already matches/exceeds the real HKUDS pattern. There is no richer upstream pipeline to "upgrade" to.

### 1.2 Empirical: the 4KB cap is currently never breached (so the premise of "v0.2 needed for size" is false)

Probe (`~/.hermes/hermes-agent/venv/bin/python3`, current `data_grounding.py`):

| window n | rendered bytes | rows kept | cap |
|---|---|---|---|
| 5   | 1,103 | 5  | 4096 |
| 42  | 1,808 | 42 | 4096 |
| 60  | 1,809 | 60 | 4096 |
| 200 | 1,812 | 200→trimmed | 4096 |

A 200-day block renders at **1,812 bytes** after the existing `_trim_to_high_info_rows` (last-5 + 8 weekly). The 4KB ceiling has **massive headroom**; size pressure is not a real failure mode at current row widths. The compression task is therefore about *information quality of the kept rows*, not about fitting the budget.

### 1.3 Prior art for deterministic OHLCV→LLM compression

- **narrata** (https://github.com/marcinmiklitz/narrata, PyPI `narrata` v0.1.4, **MIT**, py>=3.11): "pure Python, deterministic, **does not make LLM API calls**." Reports **~35–41x** token compression on a 251-day AAPL frame (`df.to_string()` ~9,000 tok → `narrate(df)` ~260 tok, measured with tiktoken gpt-4o). Techniques: SAX symbolic encoding, regime detection (`ruptures`), indicators (`pandas-ta-openbb`), support/resistance, sparklines, digit-splitting for tokenizer robustness. Core deps numpy/pandas/scipy/toons; advanced features are **optional extras** (`ruptures`, `tslearn`, `pandas-ta-openbb`). Crucially it **"silently omits sections it cannot compute — no wasted tokens on placeholder text"**, which is exactly the silence-contract behavior B46 wants.
- **theocouerbe financial_agent** (https://www.theocouerbe.com/financial_agent.pdf): strict pattern — LLM is confined to language tasks; *all numeric computation is deterministic, auditable, reproducible*. Their abstraction layer gives the LLM only a compact **data-quality profile**, never raw OHLCV; rule-based template fallback if the LLM fails. Directly endorses the fail-closed / no-LLM-in-numeric-path posture.
- **SimplyLiz/ContextCompressionEngine** (https://github.com/SimplyLiz/ContextCompressionEngine): "deterministic engine achieves 1.3–6.1x compression with zero latency and zero cost… in most scenarios it compresses tighter than an LLM." Confirms deterministic dedup + budget-packing beats LLM summarization for structured/tabular content. Reinforces: do not reach for an LLM layer.
- **SAX** for the "Layer-0 symbolic" option: tslearn `SymbolicAggregateApproximation`, `pyts.approximation.sax`, `seninp/saxpy`. All deterministic; but they pull numpy/scikit dependencies. For a 4KB-bounded grounding block, SAX is overkill (see §4 pitfalls).
- **Information-theoretic truncation** literature (CIDR 2026 "Economics of LLM-Based Compression" https://www.vldb.org/cidrdb/papers/2026/p34-kipf.pdf; arXiv 2407.08892 prompt-compression survey): the genuinely *information-theoretic* methods (arithmetic coding, LLMLingua/Selective-Context perplexity scoring) **require a model** to score self-information/perplexity. There is **no model-free "information-theoretic truncation"** — the closest deterministic analog is a hand-rolled saliency heuristic (variance / |return| / volume-z / regime-change magnitude). The TODO's "Layer 4 information-theoretic score" must therefore be implemented as a *deterministic saliency proxy*, not true Shannon self-information.

## 2. Recommended implementation approach for THIS repo

**Scope:** keep `data_grounding.py` self-contained, **stdlib-only**, deterministic, no new deps. Replace the misleading 5-layer TODO with a 2-stage deterministic compaction that is honestly named. Do not add narrata as a dependency (heavy optional extras, py>=3.11, and a 4KB block doesn't need SAX/regime sections).

### Files
- **Edit `hermes_quant/grounding/data_grounding.py`** (the only file that changes). Tests in `tests/grounding/test_data_grounding.py` stay green; add new tests.

### Design — `_trim_to_high_info_rows` v0.2 (deterministic, no LLM)

Replace the v0.1 body with a budget-aware loop that composes two deterministic layers, then update the docstrings at `:13–27` and `:298–319` to stop claiming an LLM pipeline.

1. **Layer A — microcompact row encoding (the only honest "Layer 0" from the TODO).**
   Add a compact render mode `_render_full(block, *, compact: bool=False)`. In compact mode emit a narrower OHLCV line (drop the 80-char ruler, shrink column widths, format prices with `f"{x:.2f}"` and volume in `k`/`M` shorthand, e.g. `1.00M`). This is the deterministic float/row micro-encoding. It must **not** change citation IDs (verifier in `verifier.py:166` re-renders the block and substring-matches numbers, so the *exact numeric token* must still be present and word-boundary-isolated — keep 2dp closes; do not round to "6-char float repr" if that drops a digit the analyst might cite).

2. **Layer B — deterministic saliency keep (honest replacement for "Layer 3 dedup + Layer 4 info-theoretic").**
   When even compact render > 4KB, rank non-recent bars by a **deterministic saliency score** and keep the top-k that fit:
   - `saliency(bar_i) = w1*|close_i - close_{i-1}|/close_{i-1}  (return magnitude)`
   - `+ w2*(range_i = (high_i-low_i)/close_i)  (intraday volatility)`
   - `+ w3*z(volume_i)  (volume surprise vs window mean/std)`
   - Always force-keep the **latest 5 bars** (recency, already a test invariant) and the **window min-close and max-close bars** (so verifier can trace the cited range). This is "semantic dedup + info-theoretic" expressed as a deterministic, reproducible heuristic — fixed weights, tie-break by date descending, no RNG.
   - Pack greedily until the *next* added row would exceed `_MAX_RENDER_BYTES`; this is the deterministic adaptive truncation.

3. **Silence contract / fail-closed.** Keep the existing guarantees and make them explicit:
   - Empty bars → return `(bars, ids)` unchanged (already done at `:320`). No fabricated rows.
   - The `HARD_RULE_PREAMBLE` is appended **last, verbatim, always** — even after maximal trimming. Add an assertion path: if compact + saliency-keep *still* can't fit the preamble + ≥ latest-5 within 4KB, fall back to **latest-5-only + preamble** (never drop the preamble; drop data rows first). This is the fail-closed rule: better to emit fewer ground-truth rows than to emit an uncited prompt.
   - No LLM call anywhere in the default path (there is no non-default path either — keep it that way).

4. **Determinism test additions** (new, in `tests/grounding/test_data_grounding.py`):
   - `render_for_prompt(block) == render_for_prompt(block)` byte-identical across 100 repeats.
   - Saliency keep is order-stable: same input → same kept dates.
   - A pathological wide-volume block (e.g. 9-figure volumes, 5dp closes) still renders ≤4KB *with* the preamble verbatim.
   - Min-close and max-close bars survive trimming (so the verifier can trace `window_low`/`window_high` claims).

### What NOT to change
- `HARD_RULE_PREAMBLE` constant (`:44–50`) — byte-verbatim, tested at `:116`, `:131`.
- Citation-ID scheme `gt_{SYMBOL}_{YYYYMMDD}_close` and `_quote` — `verifier.py:167` depends on it.
- The 2dp close formatting — `_number_in_gt_text` (`verifier.py:71`) uses word-boundary matching `(?<![0-9.])…(?![0-9.])`; changing decimal places changes which analyst claims trace. Keep `:.2f` for closes (current code uses `:.4f`; **note**: switching 4dp→2dp is a verifier-coupling change — keep current `.4f` unless you also re-run `tests/grounding/test_verifier.py`).

**stdlib only.** `math`, `statistics`, `datetime`, `dataclasses`, `typing` — all already imported in `data_grounding.py`. No new runtime dependency.

Rejected dependencies (with reason):

## 4. Pitfalls & rails

- **No-LLM rail (hard):** the TODO literally names two LLM layers (per-window summary, iterative update). Implementing them as written breaks B46. The corrected design has zero LLM calls.
- **Verifier coupling (subtle):** `verifier.py` re-renders the block and substring-matches numbers with word boundaries. Any change to float formatting, comma-thousands, or which rows survive trimming changes *which analyst claims pass verification*. Min/max-close rows must survive so range claims trace. Run `tests/grounding/test_verifier.py` after any render change.
- **Silence contract:** never synthesize placeholder rows; empty input → empty output. narrata's "silently omit sections you can't compute" is the model.
- **Fail-closed ordering:** preamble is sacred; drop data rows before ever dropping or paraphrasing the preamble. If nothing fits, emit latest-5 + preamble.
- **Determinism:** fixed saliency weights, deterministic tie-break (date desc), no RNG, no wall-clock. Byte-identical render across repeated calls is a test.
- **No-lookahead:** saliency uses only in-window past bars (`close_{i-1}` within the already-as-of window); never reference data after `asof`. The builder already slices to lookback, so this holds as long as scoring stays within the passed bars.
- **Default-OFF:** this is an internal renderer, not a strategy — no `.env` flag needed; it ships behind the same green-tests gate. But the *behavioral change* (which rows are kept) should be guarded so a regression in a downstream analyst is attributable: keep v0.1 trim reachable via a module constant `_TRIM_POLICY = "saliency"` (default) | `"weekly"` for one release, then remove.
- **"Information-theoretic" is a misnomer here:** real info-theoretic compression needs a model. Name the function `_saliency_keep`, not `_information_theoretic_truncate`, to avoid future confusion. Document it as a deterministic proxy.
- **Premise check:** size pressure does not currently exist (§1.2, 1,812 bytes for 200 bars). The justified work is *information quality* (keep the volatile/high-volume bars, not arbitrary Fridays), plus a hard fail-closed guard for pathological wide rows — not a budget rescue.
