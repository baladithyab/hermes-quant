# B24 — 5-section structured system-prompt template + "frozen persistent memory"

**Date:** 2026-05-31
**Item:** B24 / A7 — RESEARCH-THEN-DECIDE
**Verdict: DO_NOT_BUILD** (already-covered; both halves are structurally present and the one novel FinMem piece — self-adaptive risk-character — is an explicit rail violation per ADR-0080).

---

## 1. What B24 actually references (decisive external findings)

The phrase "5-section structured system-prompt template + frozen persistent memory" is the **FinMem** pattern (Yu et al., AAAI-SS 2024, arXiv:2311.13743), NOT primarily HKUDS/AI-Trader. The research direction's pointer to AI-Trader was a misdirection — deepwiki on `HKUDS/AI-Trader` confirms it has **no** 5-section system prompt and no frozen-memory concept: it uses `SKILL.md` files + a `_generate_stock_analysis_summary` market-snapshot prompt; "persistence" there = registered `agent_id`/`token` + locally-cached SKILL files (https://deepwiki.com/HKUDS/AI-Trader).

### FinMem (the real source — pipiku915/FinMem-LLM-StockTrading)
- deepwiki on `pipiku915/FinMem-LLM-StockTrading`: the trading prompt is assembled in `trading_reflection` (`puppy/reflection.py`) from distinct sections: **(1) Profile/Character** (`LLMAgent.character_string`), **(2) Momentum**, **(3) Memory: short/mid/long/reflection layers**, **(4) implicit rules**, **(5) Output Format** (Pydantic + `guardrails`).
- **"Frozen": the `character_string` is "a static string set during initialization and reused unchanged every trading day."** That is the literal meaning of "frozen persistent memory" — the persona/profile block is set once and never regenerated.
- **Persistence:** the layered long-term memory (`BrainDB`) is `pickle`d to `state_dict.pkl` at checkpoint; reloaded on resume. Retrieval score `γ = recency + relevancy + importance` with per-layer decay (`yu2024finmem.pdf`; ar5iv 2311.13743).
- FinMem's profiling module = (a) professional background, (b) three risk inclinations: risk-seeking / risk-averse / **self-adaptive** (flip conservative when 3-day cumulative return < 0).

### Structured-system-prompt best practice (what "5 sections" canonically means)
- arXiv:2504.02052 (*From Prompts to Templates*) merges LangGPT/CRISPE/Saravia/Google taxonomies into ~7 components; the load-bearing five are: **Profile/Role, Context/Background (data), Directive/Instructions, Constraints, Output-Format/Style.**
- Palantir + promptingguide.ai LLM-Agents + "Architecture of Agency" (2026): an agent system prompt = identity/scope + tool catalog + reasoning protocol + **hard constraints/rails** + **output format** + escalation conditions; "tiered constraint model" (explicit priority layers).
- mightybot.ai (structured-prompt-formats): keep persona/sections as XML-tag / prose blocks, keep **JSON only at the API boundary** (output schema) — exactly what this repo already does (markdown SYSTEM/USER split + JSON-only output).

Sources: arXiv:2311.13743 (ar5iv.labs.arxiv.org/html/2311.13743, suchow.io/assets/docs/yu2024finmem.pdf, ojs.aaai.org AAAI-SS v3i1.31290); deepwiki pipiku915/FinMem-LLM-StockTrading + HKUDS/AI-Trader; arXiv:2504.02052; palantir.com/docs/foundry/aip/best-practices-prompt-engineering; promptingguide.ai/research/llm-agents.

## 2. What this repo ALREADY has (codebase grounding)

### (a) The 5-section template is already implemented — per role.
`hermes_quant/aggregators/llm_committee.py` loads 7 markdown templates from `aggregators/prompts/` and splits each on literal `SYSTEM:`/`USER:` markers (`_split_system_user`, L176-190). `portfolio_manager.md` contains **all five canonical sections**:
1. **Profile/Role** — "You are the Portfolio Manager — the deep-tier final-synthesis voice…" (static, in SYSTEM).
2. **Data/Context** — `{baseline_signal_json}`, `{analyst_views_json}`, `{prior_turns_json}` (USER).
3. **Memory** — `{lessons_block}` ("Lessons from prior decisions and outcomes:").
4. **Constraints/Rules** — "Final-size rule", "Silence-by-default rule (mandatory)", "deterministic risk gate (ADR-0004) is the final authority".
5. **Output Format** — explicit JSON schema, "no prose outside JSON", enforced by Pydantic `PortfolioDecision` (`extra="forbid"`).

Every other role template (`bull_bear.md`, `research_manager.md`, `risk_*.md`, `devils_advocate.md`) follows the same structured SYSTEM/USER + JSON-schema-output shape. So the "5-section structured system prompt" is **done** — it's just not labeled "5-section" and is per-role rather than one monolith (correct, given the committee architecture).

### (b) The SYSTEM block is already "frozen."
The SYSTEM half of each template is a **constant string in a versioned file** — set once, reused unchanged every tick, never regenerated by an LLM. That IS FinMem's frozen `character_string`. Forensics: `_prompt_hash` (SHA-256 over system+user) is persisted in every `CommitteeTurn.metadata`, so any drift to the "frozen" persona is detectable from the journal (ADR-0037). `tests/agents/research_debate/_legacy_prompt_hashes.json` already pins prompt hashes — i.e., the freeze is test-enforced.

### (c) "Persistent memory" is already built, and it is SUPERIOR to FinMem's pickle/recency scheme for money-software.
- `memory/retriever.py` — BM25 (rank-bm25 + 30-line Okapi fallback) over append-only `reflections.jsonl`, same/cross-ticker/cross-sector buckets, **Oracle-Fallacy guard** (any reflection with `tau_observable >= asof` excluded *before* k-selection; arxiv:2605.19337 §4.2; regression test `tests/memory/test_oracle_fallacy.py`). Injected into PM/RM prompts only (ADR-0042 §167: debaters stay persona-clean), gated `HERMES_QUANT_MEMORY_INJECT=1` default-OFF.
- `memory/reflector.py` (Layer 2, `HERMES_QUANT_REFLECTION=1`) — produces reflections + deterministic `tau_observable`; self-grade-refusal invariant (the PM model cannot reflect on its own outcome).
- `memory/weekly_retro.py` (Layer 4, ADR-0081, `HERMES_QUANT_WEEKLY_RETRO=1`) — **FINMEM-derived** access-counter + tiered decay (`HALF_LIFE_DAYS`, `RECENCY_EXPIRE_EPSILON`, `IMPORTANCE_BONUS_K`) promote/expire over `beliefs.jsonl`. This is the *deterministic* re-implementation of FinMem's `γ = recency+relevancy+importance` layered memory, minus the LLM-decides-what-to-keep risk. `load_active_beliefs` applies the same Oracle guard at the belief level + bumps the FINMEM access counter.

ADR-0042 §16-19 explicitly cites TauricResearch (5-same+3-cross injection), Vibe-Trading (FTS5 auto-injected-every-run), virattt/ai-hedge-fund — the persistent-memory survey B24 implies was *already done* and shipped as ADR-0042/0081.

### (d) The one genuinely-novel FinMem piece is a documented rail violation.
FinMem's distinctive profiling feature is the **self-adaptive risk-character** (auto-flip to conservative on 3-day cumulative loss). ADR-0080 §131 + §168 + capability-map §3 list this **by name** as "Explicitly NOT adopted (rail violations)" — admitted only as *advisory persona-calibration telemetry* (W3 monthly-meta, default-OFF, recommendations-only), **never auto-applied to limits**. So the part of B24 that isn't already built is the part we have a standing decision NOT to build.

## 3. Scope verdict: DO_NOT_BUILD

| B24 sub-claim | Status |
|---|---|
| 5-section structured system prompt | **DONE** — `aggregators/prompts/*.md` (SYSTEM/USER + Pydantic JSON output), per role. |
| Frozen persona/profile | **DONE** — SYSTEM block is a versioned constant string; `_prompt_hash` + `_legacy_prompt_hashes.json` enforce the freeze. |
| Persistent memory | **DONE & SUPERIOR** — ADR-0042 BM25+Oracle retriever (`reflections.jsonl`) + ADR-0081 access-counter/decay beliefs (`beliefs.jsonl`); Oracle-guarded, no-lookahead, default-OFF. |
| FinMem layered recency/relevancy/importance | **DONE deterministically** — `weekly_retro.py` FINMEM promote/expire (no LLM-decides-keep). |
| FinMem self-adaptive risk-character | **DO NOT BUILD** — ADR-0080 rail violation (policy mutation of risk posture); advisory-telemetry only, deferred to W3. |

**Is "frozen persistent memory" redundant with the existing BM25/Oracle retriever injection?** Yes. "Frozen" maps to the already-constant SYSTEM block (test-pinned by prompt-hash); "persistent memory" maps to the already-shipped retriever + belief store, which is *more* rigorous than FinMem (Oracle/no-lookahead guard, deterministic decay, default-OFF, append-only immutable source). Building a separate "5-section + frozen memory" component would **duplicate** ADR-0037 (prompt structure), ADR-0042 (retriever), and ADR-0081 (belief decay), and would re-open a rail decision ADR-0080 already closed.

### If a future ticket wants the *labeling/polish* benefit only (NOT B24 as written)
The only non-redundant, rail-safe micro-improvement would be a **documentation/lint** pass: add a one-line section-comment header to each `prompts/*.md` (`# section: profile | data | memory | constraints | output`) plus a test asserting each template contains all five section markers + the SYSTEM/USER split + a JSON-output schema. That is a ~30-line *quality* change (fold into B18 "render_X helpers" / prompt-hygiene), not a capability build, and does NOT change any prompt bytes (the hashes/`_legacy_prompt_hashes.json` stay valid because comments live above the `SYSTEM:` marker, which `_split_system_user` already discards, L185-189). Recommend FOLDING that optional hygiene check into B18 rather than tracking B24 separately.

## 5. Pitfalls / rails (why building is actively harmful here)
- **Determinism / prompt-hash freeze:** any rewrite of `prompts/*.md` SYSTEM blocks breaks `_legacy_prompt_hashes.json` and every `prompt_hash` audit row — a regression, not a feature.
- **No-lookahead:** FinMem's recency/pickle memory has NO Oracle guard; importing it naively would *regress* the no-lookahead invariant the repo spent ADR-0042 §4.2 building. The existing retriever's `tau_observable >= asof` exclusion is the rail.
- **Silence-contract / default-OFF / fail-closed:** memory injection is already `HERMES_QUANT_MEMORY_INJECT=1` default-OFF, fail-closed (`(none)` on any exception, non-blocking). A new memory path would have to re-earn all of that.
- **Rail violation:** FinMem self-adaptive risk-character = policy mutation of risk posture → forbidden by ADR-0080 / capability-map §3 (advisory-telemetry only).
- **Anti-duplication:** debaters (bull/bear/risk) must NOT see the memory block (ADR-0042 §167) — a generic "inject frozen memory into the system prompt every run" (the Vibe-Trading pattern) would violate the persona-cleanliness invariant.
