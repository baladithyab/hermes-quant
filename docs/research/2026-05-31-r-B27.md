The induction *method* is settled and low-risk (a deterministic single-feature decision
stump + Wilson-lower-bound precision gate + trial-count overfit guard, stdlib + the

single-digit) set of profitable trades is precisely the failure mode the literature warns
against. So B27 is the same shape as `catalyst/graph_mining.py` (D80) was: ship the
designed, default-OFF, propose-only, silence-by-default module so it is ready, and let it
stay inert (returns `[]`, writes nothing) until the journal accretes enough resolved

This is BUILD-the-skeleton, DEFER-the-activation — not DO_NOT_BUILD. The module is worth
landing now because (a) it forces B26's settlement plumbing to actually resolve trades, and
(b) the design encodes the overfit rails that must exist before any auto-rule touches money.

## 1. Decisive external findings (with citations)

### 1a. Method choice for SMALL resolved-trade sets — "simplicity first"
- **Holte 1993, "Very Simple Classification Rules Perform Well on Most Commonly Used Datasets"**,
  *Machine Learning* 11:63–90, https://doi.org/10.1023/A:1022631118932 (PDF:
  https://webdocs.cs.ualberta.ca/~holte/Publications/simple_rules.pdf). Single-attribute
  "1-rules" (1-level decision trees) are on average only ~3.1 pp less accurate than C4.5 on
  14/16 standard datasets. **This is the canonical argument that for small/noisy data the
  simplest auditable rule generalizes about as well as a complex learner** — and is exactly
  what an "if X then direction" shadow rule is.
- **OneR R-package vignette** (von Jouanne-Diedrich),
  https://cran.r-project.org/web/packages/OneR/vignettes/OneR.html — explicitly names the
  overfit trap: the *original* 1R bucketed numeric attributes "until best accuracy," which
  "is the definition of overfitting" producing "tons of rules." Fix: few bins (≈ #classes)
  and chi-square tie-breaking. → **For us: use ≤1 numeric threshold per rule, depth-1 only.**

### 1b. Why NOT RIPPER and NOT Apriori on tiny n
- **RIPPER / Cohen 1995, "Fast Effective Rule Induction"**, ICML, PDF:
  https://sci2s.ugr.es/keel/pdf/algorithm/congreso/ml-95-ripper.pdf; Weka JRip docs:
  https://weka.sourceforge.io/doc.stable/weka/classifiers/rules/JRip.html. RIPPER is
  designed for **large** noisy datasets (scales near-linearly to hundreds of thousands of
  examples), needs a grow/prune split (2/3 grow, 1/3 prune) and MDL stopping, and is the
  paper's own words "unduly sensitive to the small-disjunct problem." A practitioner thread
  (RapidMiner) shows on ~100 subjects JRip's ruleset accuracy swings up to 20 pp vs CV.
  **Verdict: RIPPER is wrong for single-digit-to-dozens resolved trades.** (Also: no
  `wittgenstein` package installed in the venv — see §3.)
- **Apriori / association rules** — Wikipedia Association rule learning,
  https://en.wikipedia.org/wiki/Association_rule_learning : "a rule needs a support of
  several hundred transactions before it can be considered statistically significant …
  datasets often contain thousands or millions of transactions." Multiple sources stress
  **lift** must be checked, not just confidence (high confidence with lift≈1 = no real
  association; the bread→milk lift-1.03 cautionary tale,
  https://mcpanalytics.ai/articles/association-rules-apriori-practical-guide-for-data-driven-decisions).
  **Verdict: Apriori needs hundreds of transactions; over-kill and unsafe at our n.** No
  `mlxtend` in the venv either.

### 1c. The overfit / multiple-testing guard (the load-bearing finding)
- **Bailey & López de Prado 2014, "The Deflated Sharpe Ratio"**,
  https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf, and "Pseudo-Mathematics and
  Financial Charlatanism", https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2308659:
  "After a sufficient number of trials, it is guaranteed that a researcher will always find a
  misleadingly profitable strategy, a false positive." Selection bias under multiple testing
  (SBuMT) means **you must count the number of candidate rules examined and discount for it.**
- **Harvey & Liu, "Backtesting"** (Duke),
  https://people.duke.edu/~charvey/Research/Published_Papers/P120_Backtesting.PDF : "**only
  seven trials are needed to obtain a spurious two-year backtest with in-sample Sharpe > 1.0
  while the expected out-of-sample Sharpe is zero.**" The killer fact for B27: if we test one
  candidate stump per feature (~6–10 features), we are already in spurious-discovery
  territory unless we discount. Also gives "minimum profitability hurdle" framing: given α,
  #obs, and #tests, what return must a rule clear.
- **Jensen & Schmill 1997, "Adjusting for Multiple Testing in Decision Tree Pruning"**,
  https://proceedings.mlr.press/r1/jensen97a.html — the academic bridge: tree induction is
  itself multiple testing (it picks the best of many candidate splits), so the split's
  apparent accuracy must be Bonferroni-corrected for the number of candidates examined. →
  **Bonferroni-correct the per-rule significance by the number of features/thresholds tried.**
- **GT-Score 2025**, https://www.mdpi.com/1911-8074/19/1/60 — recommends a practical
  **`n_min = 50` minimum-trade threshold** ("minimally stable sampling base … reduces
  sensitivity to a handful of outlier trades"); penalize parameterizations with fewer trades.
  (We adopt the repo's existing `MIN_SAMPLE = 20` as the floor and treat 50 as the
  "confident" tier — see §2.)

### 1d. Small-sample precision interval — Wilson, not Wald
- **Brown, Cai & DasGupta 2001/2002, "Interval Estimation for a Binomial Proportion"**, and
  **AFIT "Recommended Confidence Intervals for a Binomial Proportion"**,
  https://www.afit.edu/STAT/statcoe_files/12_Binomial%20proportion%20intervals%20DRAFT%20-%20PA%20copy(1).pdf:
  the Wald (normal-approx) interval is "chaotic and unacceptably poor," even at samples
  "deemed sufficient," and especially at extreme p (a rule with 5/5 wins). The **Wilson score
  interval** is the recommended small-n binomial CI; **Wilson + continuity (Yates) correction**
  is advised when n is small or p is near 0/1 (Towards Data Science, "Five Confidence
  Intervals for Proportions"; UCL Wallis). → **Gate a rule on the Wilson LOWER bound of its
  win-rate, not the point estimate.** A rule that is 4/4 has point precision 1.0 but a Wilson
  lower bound around ~0.51 at 95% — so a perfect-but-tiny rule is correctly NOT trusted.

### 1e. Deterministic, no-LLM, auditable induction primitive (already in the venv)
- **scikit-learn 1.8.0 `DecisionTreeClassifier(max_depth=1)`** = a decision stump. Confirmed
  via deepwiki(scikit-learn): read `tree_.feature[0]`, `tree_.threshold[0]`,
  `tree_.children_left/right`, and `tree_.value[leaf][0]` (class proportions/counts) to emit a
  fully auditable `if feature <= threshold then class` rule; `export_text(..., show_weights=True)`
  renders the human-readable if-then.
  Docs: https://scikit-learn.org/1.8/modules/generated/sklearn.tree.export_text.html .
  **`random_state` IS required for determinism** even at depth 1, because ties in impurity
  improvement are broken randomly — set `random_state=0` for a bit-for-bit reproducible rule.
  (We can also implement the stump in pure stdlib — a 1R scan over candidate thresholds — to
  avoid even the sklearn dependency; see §3 recommendation.)

## 2. Recommended implementation for THIS repo

### 2a. The template already exists: `catalyst/graph_mining.py` (D80 / ADR-0080)
B27 is the **same wave pattern** as graph mining, applied to the settlement journal instead
of the propagation log. Mirror it beat-for-beat:
- joins an append-only log of realized outcomes (there: `propagation-log.jsonl`; here:
  the resolved entries of `~/.hermes/quant/journal.md` via `journal.reader`),
- **PROPOSES** edits and never auto-applies (there: `graph-mine-candidates.json` for operator
  review; here: `shadow-rule-candidates.json`),
- **silence-by-default** on empty/insufficient corpus (returns `{}` / writes nothing),
- **DEFAULT-OFF** behind a flag (there `HERMES_QUANT_GRAPH_MINING`; here a new
  `HERMES_QUANT_SHADOW_RULE_MINING`), flag-off is a bit-for-bit no-op,
- **reuses** `MIN_SAMPLE`/`MIN_HIT_RATE` rather than redefining thresholds,
- carries an **Oracle-Fallacy provenance tag** and **never re-ingests its own output**.

### 2b. New file: `hermes_quant/shadow/rule_mining.py`
Design (grounded in `profitability.py` + `graph_mining.py` conventions):

```
HERMES_QUANT_SHADOW_RULE_MINING  # default "0"; flag-off => mine_rules() returns [], writes nothing
MIN_SAMPLE  = 20   # imported from catalyst.profitability (the repo's existing floor; do NOT redefine)
CONFIDENT_N = 50   # GT-Score "minimally stable" tier — a rule is "confident" only at n>=50
MIN_WILSON_LB = 0.60  # Wilson lower bound a rule's win-rate must clear (mirrors MIN_HIT_RATE=0.6)

@dataclass(frozen=True)
class InducedRule:
    feature: str           # one of the auditable features in 2c
    op: Literal["<=", ">", "==", "in"]
    threshold: float | str # numeric cut OR categorical value
    direction: Literal["buy","sell"]   # the action the rule recommends
    n: int                 # resolved trades the rule covers (support)
    wins: int              # of those, # profitable (alpha_return > 0)
    win_rate: float        # wins/n (point estimate — NOT the gate)
    wilson_lb: float       # 95% Wilson lower bound (THE gate)
    lift: float            # win_rate / base_rate (must be > 1.0 + margin)
    n_trials_tested: int   # # candidate (feature,threshold) pairs scanned -> Bonferroni
    bonferroni_p: float    # corrected significance of this rule vs base rate
    verdict: Literal["PROPOSE","INSUFFICIENT_SAMPLE","FAILS_WILSON","FAILS_LIFT","FAILS_BONFERRONI"]
    reason: str            # human-readable, e.g. "confidence > 0.72 -> buy (24/30 win, wilsonLB=0.63)"
    provenance: str        # "shadow.rule_mining.mine_rules"
    generated_at: str
```

Induction algorithm (deterministic, no LLM, single-feature = depth-1 = a 1R/decision stump):
1. Load resolved entries (`is_resolved()`) from the journal; build a feature matrix (§2c).
   Silence-by-default: `< MIN_SAMPLE` resolved profitable rows => return `[]`.
2. Label = `1 if alpha_return > 0 else 0` (the "profitable" target; alpha not raw — matches the
   journal's alpha-vs-benchmark honesty and `SettlementEntry.alpha_return`).
3. For each candidate feature, scan candidate thresholds (numeric: the few midpoints between
   sorted distinct values, capped to ≤5 bins per OneR's anti-overfit guidance; categorical:
   each level). Each (feature,threshold,direction) is **one trial** — count them
   (`n_trials_tested`) for the Bonferroni correction (Jensen 1997).
4. For each candidate compute: support `n`, `wins`, point `win_rate`, **Wilson lower bound**
   (stdlib, see §3), `lift = win_rate / base_rate`, and a one-sided binomial p-value vs the
   base rate, Bonferroni-corrected by `n_trials_tested`.
5. **Gates (ALL must pass to PROPOSE):** `n >= MIN_SAMPLE` AND `wilson_lb >= MIN_WILSON_LB`
   AND `lift >= 1.0 + margin` AND `bonferroni_p <= 0.05`. Otherwise the verdict names the
   failing gate. Keep the **top 3–5** surviving rules ranked by `wilson_lb` (NOT win_rate, so
   tiny-but-perfect rules can't win).
6. Optional cross-check (the held-out guard): time-order the resolved trades, fit the candidate
   on the older 70%, confirm `wilson_lb` still clears on the newer 30%. This is the
   no-lookahead, no-snooping rail (Harvey & Liu: OOS is imperfect but a candidate that fails it
   is clearly fragile). Skip only when `n < CONFIDENT_N` (not enough to split) and label such
   rules `verdict=PROPOSE` but `confident=False`.

### 2c. Feature surface — and the B26/data-gating blocker
The natural features are `SettlementEntry`'s decision-time fields, which are **lookahead-safe**
(known at decision, before the outcome): `direction` (-1/0/1), `confidence` (0–1),
`target_position_pct`, `asset_class`, `benchmark_symbol`, `hitl_kind`, and — most valuable —
the **per-analyst votes** in `per_analyst_components` (`analyst`, `direction`, `confidence`,
`weight`). The induced rules would then be the *learned* analogues of the hand-coded ones
(`SemanticOnlyRule`, `TrendFollowingRule`, etc.) — e.g. "if classical_ta voted AND
confidence > 0.7 then follow." The label `alpha_return` is the **outcome** and is NEVER a
feature (no-lookahead).

**BLOCKER (verified on disk):** `journal/reader.py:173` sets
`per_analyst_components=[]` — the analyst votes are written to the prose body but are **not
round-tripped** from the markdown meta block. So today the richest features are unreadable
after a round-trip. B26 (or a small writer change) must persist `per_analyst_components` into
the META block (or B27 must read the unresolved-but-richer in-memory entries directly from the
settlement loop). Until then the feature set is the thin scalar set (direction/confidence/
asset_class), which is still inducible but much weaker.

## 3. Exact libraries / APIs

- **Wilson score interval — stdlib only.** No scipy needed; it's a closed form. With z=1.96
  for 95%: given `k` wins of `n`, `p = k/n`, `z2 = z*z`,
  `centre = (p + z2/(2n)) / (1 + z2/n)`,
  `half = (z/(1+z2/n)) * sqrt(p*(1-p)/n + z2/(4n*n))`,
  `wilson_lb = centre - half`. (Yates continuity correction optional for n<~30 / extreme p.)
  This is the single most important numeric primitive and needs **no dependency**.
- **Binomial p-value / Bonferroni:** `scipy.stats.binomtest(k, n, base_rate, alternative="greater").pvalue`
  (scipy **1.17.1** present) then `min(1.0, p * n_trials_tested)`. Can also be done with
  `math.comb` in stdlib if avoiding scipy is preferred.
- **Decision stump (optional):** `sklearn.tree.DecisionTreeClassifier(max_depth=1, random_state=0)`
  + `export_text(...)` (**sklearn 1.8.0** present, `pandas 2.3.3`, `numpy 1.26.4`). The
  `tree_.feature/threshold/value` read-out gives the auditable rule. **`random_state=0` is
  mandatory for determinism** (tie-breaking). RECOMMENDATION: because the depth-1 1R scan is
  trivially implementable in **pure stdlib** and the repo prizes dependency-light shadow code
  (see `shadow/pmcc.py` vendoring its own Black-Scholes "to stay dependency-light"), prefer a
  **stdlib 1R scan** for the production path and keep sklearn only as an optional
  cross-validation oracle. Either way: no LLM, fully deterministic, fully auditable.
- **NOT available / NOT to add:** `mlxtend` (Apriori) and `wittgenstein` (RIPPER) are **not
  installed** in `~/.hermes/hermes-agent/venv` — and per §1b neither is appropriate for the
  sample size anyway. Do not add them.

## 4. Pitfalls + rails to respect

- **No-lookahead (non-negotiable):** the label `alpha_return`/`raw_return` is the OUTCOME and
  must never appear as a feature. Features are decision-time fields only. The optional
  hold-out split must be **time-ordered** (older→newer), never random, never shuffled — a
  random split leaks future info into the "train" fold for autocorrelated returns.
- **Determinism:** stdlib 1R is deterministic; if sklearn is used, pin `random_state=0`. Sort
  candidate features and thresholds in a fixed order so ties resolve identically every run.
- **Overfit on tiny n — the central risk.** Guards, all required: (1) `n >= MIN_SAMPLE (20)`
  support floor; (2) gate on **Wilson lower bound**, not point win-rate (kills 4/4-looks-perfect
  rules); (3) **lift > 1** (a rule that "predicts buy when everything is already buy" has lift≈1
  and adds nothing — the bread→milk trap); (4) **Bonferroni-correct** the significance by the
  number of candidate (feature,threshold) pairs tested (Jensen 1997 / Harvey-Liu: 7 trials =>
  spurious Sharpe>1); (5) cap rules at **depth 1** and **≤5 numeric bins** (OneR anti-overfit);
  (6) emit at most **3–5** rules.
- **Silence-contract / silence-by-default:** empty or sub-MIN_SAMPLE corpus => return `[]`,
  write nothing, the candidate file is not even created (mirror `graph_mining.write_candidates`
  and `profitability.measure_profitability`). The weekly cron is a change-detecting watchdog:
  silent unless a NEW rule crosses the bar.
- **Default-OFF / fail-closed:** behind `HERMES_QUANT_SHADOW_RULE_MINING` (default "0");
  flag-off is a bit-for-bit no-op. On any read/parse error, log-warn and return `[]` (never
  raise into a caller) — the `profitability.py`/`pmcc.py` best-effort idiom.
- **Propose-only — never auto-apply (the money rail):** induced rules are written to a
  candidate JSON for operator review and NEVER mutate `default_rules()` or any live decision
  path. The deterministic risk gate stays the final authority; this loop can never edit it.
  "Hard rules over learned policy" is preserved.
- **Oracle-Fallacy / model-collapse guard:** tag every candidate with
  `provenance="shadow.rule_mining.mine_rules"` and **never re-ingest the candidate file** — only
  the journal (external realized outcomes) is read back, exactly as `graph_mining.py` only reads
  `propagation-log.jsonl` and never its own `graph-mine-candidates.json`.
- **Survivorship / settlement integrity:** rules are only as honest as the settlement that
  produced `alpha_return`. Confirm `daemon/settlement_loop.py` resolves trades lookahead-honestly
  (exit at a real future bar) before trusting any induced rule.

**Activation trigger:** land the default-OFF skeleton now; flip `HERMES_QUANT_SHADOW_RULE_MINING=1`

AND `per_analyst_components` is round-tripped (a B26 deliverable or a small writer/reader change).
Until then the module is correctly a silent no-op — same posture `graph_mining.py` held while
its corpus accreted.
