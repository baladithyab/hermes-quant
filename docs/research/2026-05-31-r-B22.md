# R-B22 — Multi-source OHLCV fallback chain: yfinance → ccxt → AlphaVantage

- Date: 2026-05-31
- Backlog item: **B22** — "C6 — multi-source data fallback chain (yfinance → ccxt → alpha_vantage with retry) (providers exist, no auto-fallback)" — resilience, P2, size M, no deps. (`docs/research/2026-05-30-backlog-consolidated.md:45`, `gaps.md:113`)
- Posture: money-software (paper). Rails: no-lookahead, determinism, silence-by-default, default-OFF rollout, fail-closed on missing credentials.

## VERDICT: BUILD (scoped) — add AlphaVantageProvider + reconcile the signature split that blocks auto-fallback

B22 is **BUILD**, but the framing in the backlog ("providers exist, no auto-fallback") is subtly wrong and the research changes the shape of the work:

1. `fetch_with_chain` (the auto-fallback engine) **already exists and is fully tested** (`hermes_quant/data/base.py:104-177`, `tests/unit/test_data_base.py:106-225`). The retry-with-backoff + RateLimitError-falls-back + DataQualityError-propagates semantics B22 asks for are **already implemented**. We do NOT rebuild this.
2. The real blocker to "auto-fallback" is a **`fetch_bars` signature split** between the two existing providers (see Decisive Findings #1). `fetch_with_chain` calls the *yfinance* signature; `CcxtProvider` uses a *different* signature and is intentionally excluded from `vendor_routing` because of it (`hermes_quant/data/vendor_routing.py:84-104`). A chain of `[yfinance, ccxt]` would `TypeError` on the ccxt fallback today.
3. Therefore B22 = (a) **add `AlphaVantageProvider`** speaking the canonical `fetch_with_chain` signature, AND (b) **adapt `CcxtProvider`** so it can sit in the same chain (a thin signature-compat shim, not a rewrite), AND (c) wire a default chain builder. Without (b), the "yfinance → ccxt → AV" chain the item literally names cannot be assembled.

The chain is **homogeneous by asset class** in practice: yfinance/AV are equity/ETF; ccxt is crypto. The literal "yfinance → ccxt → AV" is the equity story with ccxt being a no-op fallback for equities. The *useful* equity chain is **yfinance → AlphaVantage**; the crypto chain is **ccxt → (no AV equiv)**. Build the generic builder so both asset classes get a real fallback partner.

## Decisive external + codebase findings (cited)

### 1. CODEBASE — the two providers have INCOMPATIBLE `fetch_bars` signatures (the actual B22 blocker)

- `YFinanceProvider.fetch_bars(asset, timeframe, start, end, *, use_cache=True, as_of=None)` — `hermes_quant/data/yfinance_provider.py:147`. This is what `fetch_with_chain` calls positionally: `provider.fetch_bars(asset, timeframe, start, end, use_cache=use_cache)` (`base.py:143`).
- `CcxtProvider.fetch_bars(symbol, asset_class, timeframe, *, lookback_bars=200, as_of=None)` — `hermes_quant/data/ccxt_provider.py:110`. Different positional args, no `start`/`end`, no `use_cache`.
- The `DataProvider` Protocol (`hermes_quant/protocol.py:489-516`) documents the **canonical** signature as the yfinance one: `fetch_bars(asset, timeframe, start, end, *, use_cache=True, as_of=None)`. `CcxtProvider` does NOT conform to its own Protocol.
- This split is *known*: `vendor_routing.py:84-104` explicitly removes ccxt from the dispatch table and `VENDOR_LIST` (`:120-123`) with the note "Reintroduce when DataProvider Protocol unifies the signature (future ADR)." There is ALSO a latent bug at `cli/__init__.py:1450-1457` that calls `YFinanceProvider.fetch_bars(symbol=, asset_class=, timeframe=, lookback_bars=, as_of=)` — kwargs that do not exist on the yfinance signature; it would `TypeError` if that branch were exercised (it currently is not, because yfinance branch is only hit for equities and the ccxt-shaped kwargs were copy-pasted). Flag but do not fix under B22 unless cheap.
- **Decision:** `AlphaVantageProvider` MUST implement the **canonical Protocol signature** (`asset, timeframe, start, end, *, use_cache, as_of`) so it drops straight into `fetch_with_chain`. To make the literal "yfinance → ccxt → AV" chain assemblable, add a `start/end`-accepting overload to `CcxtProvider` (translate `start/end` → `since_ms`/`lookback_bars` internally) WITHOUT removing the existing kwarg path (keep both, default-OFF behavior preserved).

### 2. EXTERNAL — Alpha Vantage `TIME_SERIES_DAILY` schema, rate limits, and the "HTTP 200 + JSON Note" trap

Sources: official docs https://www.alphavantage.co/documentation/ ; support https://www.alphavantage.co/support/ ; Macroption https://www.macroption.com/alpha-vantage/ and https://www.macroption.com/alpha-vantage-api-limits/ ; AlphaLog 2026 guide https://alphalog.ai/blog/alphavantage-api-complete-guide ; pricing https://plans.apis.io/plans/alpha-vantage/alpha-vantage-plans-pricing .

- **Endpoint:** `GET https://www.alphavantage.co/query` with params `function=TIME_SERIES_DAILY`, `symbol=IBM`, `outputsize=compact|full`, `datatype=json|csv`, `apikey=...`.
- **Free-tier limits (2024→present, MUCH tighter than legacy docs):** **25 requests/day + 5 requests/minute.** (Historically 500/day, then 100/day, now **25/day**.) This is the single most important constraint — see Pitfalls.
- **`outputsize`:** `compact` = latest 100 data points (free); `full` = 20+ yrs (**PREMIUM ONLY** as of 2025). Free keys are effectively capped at the last ~100 daily bars per call.
- **`TIME_SERIES_DAILY` = raw as-traded OHLCV (free).** `TIME_SERIES_DAILY_ADJUSTED` (adjusted close + split/dividend) is now marked **"Trending Premium"** in the official docs — **premium-only**. → For a free-tier fallback, use **`TIME_SERIES_DAILY`** (raw), which matches what yfinance returns with `auto_adjust=False` (`yfinance_provider.py:211`). Do NOT default to `_ADJUSTED`.
- **Rate-limit response is HTTP 200 with a JSON body**, NOT a 4xx/429. The body is one of:
  - `{"Note": "Thank you for using Alpha Vantage! Our standard API call frequency is 5 calls per minute and 500 calls per day..."}` (legacy per-minute throttle)
  - `{"Information": "...standard API rate limit is 25 requests per day. Please subscribe..."}` (daily quota)
  - `{"Error Message": "Invalid API call. Please retry or visit the documentation..."}` (bad symbol / bad params — NOT transient).
- **JSON shape (TIME_SERIES_DAILY, compact):**
  ```json
  {
    "Meta Data": {"1. Information": "...", "2. Symbol": "IBM", "3. Last Refreshed": "2026-05-30", "4. Output Size": "Compact", "5. Time Zone": "US/Eastern"},
    "Time Series (Daily)": {
      "2026-05-30": {"1. open": "134.49", "2. high": "135.79", "3. low": "132.80", "4. close": "135.09", "5. volume": "5428898"}
    }
  }
  ```
  - Keys are **numbered string prefixes** (`"1. open"` … `"5. volume"`). **All values are strings** — must cast to float/int.
  - Dates are keyed strings (NOT an array), in **US/Eastern** ("5. Time Zone"). Dates are calendar dates (no time-of-day for daily). Must localize US/Eastern → tz-aware → hand to `validate_bars` which normalizes to tz-naive UTC.
  - `_ADJUSTED` adds `"5. adjusted close"`, `"6. volume"`, `"7. dividend amount"`, `"8. split coefficient"` — different numbering. Stick to raw `TIME_SERIES_DAILY` to keep the parser stable.

### 3. EXTERNAL — `alpha_vantage` python lib vs raw `requests` → use **raw `requests`**

- RomelTorres/`alpha_vantage` (~5K stars, https://github.com/RomelTorres/alpha_vantage) is a real wrapper but: (a) it is **not installed** in the hermes venv (`alpha_vantage: MISSING`), (b) it pulls its own transitive deps, (c) it hides the raw `Note`/`Information` body that we need for rate-limit classification, and (d) adding it violates the repo's established pattern where each provider lazy-imports ONLY the SDK it strictly needs.
- `requests==2.33.1` is **already installed** and already a base-level dependency used across the repo. AV's API is a single GET against one URL — a wrapper adds nothing.
- pandas-datareader's `AVTimeSeriesReader` exists but pulls in the whole `pandas-datareader` package — overkill.
- **Decision: raw `requests`** (lazy-imported inside the provider, mirroring how `ccxt`/`yfinance` are lazy-imported). No new hard dependency on `alpha_vantage`.

### 4. EXTERNAL/REPO — the canonical fallback pattern is ALREADY this repo's pattern (TradingAgents)

This repo already adapts TradingAgents patterns (the `_retry_with_backoff` in `yfinance_provider.py:48-98` cites `yf_retry`; `vendor_routing.py` cites ADR-0038 §D.5 "TradingAgents pattern backfill"). DeepWiki on `TauricResearch/TradingAgents` confirms the exact pattern we should mirror:

- AV requests go through `_make_api_request` in `tradingagents/dataflows/alpha_vantage_common.py`. It reads the key from env var **`ALPHA_VANTAGE_API_KEY`** via `os.getenv`, and **raises `ValueError` if missing (fail-closed)**.
- Base URL `https://www.alphavantage.co/query`; params include `function`, `apikey`, plus a `source` tag.
- **Rate-limit detection: HTTP often returns 200; they parse JSON and if an `"Information"` key contains `"rate limit"` or `"api key"`, they raise a custom `AlphaVantageRateLimitError`** — which `route_to_vendor` catches to trigger fallback. (We map this onto our existing `RateLimitError`, which `fetch_with_chain` already treats as "back off + try next provider".)
- yfinance side uses `yf_retry` (exponential backoff on `YFRateLimitError`) — the pattern hermes already copied.

→ Our `RateLimitError`/`DataProviderError`/`DataQualityError` taxonomy (`protocol.py:528-537`) is a 1:1 fit. No new exception type needed; reuse `RateLimitError` for AV throttle.

### 5. EXTERNAL — circuit-breaker vs retry: DO NOT add a circuit breaker for B22

Sources: Baeldung https://www.baeldung.com/spring-boot-circuit-breaker-vs-retry ; GeeksforGeeks circuit-breaker-vs-retry; Portkey https://portkey.ai/blog/retries-fallbacks-and-circuit-breakers-in-llm-apps ; IJIRMPS resilience paper.

- Retry = transient failures; circuit breaker = *persistent/systemic* failures + *high request volume* where you want to stop hammering a dead service. CB maintains state (Closed/Open/Half-Open).
- hermes runs at **low volume, single-process, per-tick** cadence. A CB adds stateful complexity (and a determinism hazard — CB state would make the same inputs route differently across runs) for negligible benefit. The "fallback chain + bounded retry" already gives graceful degradation.
- **Decision: bounded retry-with-backoff (exists) + ordered fallback (exists). No circuit breaker.** If volume ever rises, a CB is a *future* item, not B22. Note this explicitly to avoid scope creep.

### 6. CCXT signature confirmed (probe)

`~/.hermes/hermes-agent/venv/bin/python3` probe of ccxt **4.5.53**: `fetch_ohlcv(symbol, timeframe='1m', since=None, limit=None, params={}) -> List[list]`, rows `[timestamp_ms, open, high, low, close, volume]`, `has['fetchOHLCV']==True`. Matches `ccxt_provider.py:259` usage. yfinance is **1.4.0**, pandas **2.3.3**, requests **2.33.1**, `alpha_vantage` absent.

## Recommended implementation for THIS repo

### File 1 (new): `hermes_quant/data/alphavantage_provider.py`

A `DataProvider`-Protocol-conformant equity/ETF provider using raw `requests`, mirroring the structure of `yfinance_provider.py` / `ccxt_provider.py` (lazy SDK import, `_retry_with_backoff`-style retry, `validate_bars` wired, leaf-level `as_of` filter).

```python
class AlphaVantageProvider:
    name = "alphavantage"
    asset_classes = ["equity", "etf"]
    timeframes = ["1d"]          # free tier: TIME_SERIES_DAILY only. Intraday is premium/separate fn.
    requires_credentials = True  # FIRST credentialed provider — drives fail-closed

    def __init__(self, *, api_key=None, session=None,   # session = test seam (inject requests.Session-like)
                 outputsize="compact", retry_max_attempts=3, retry_base_delay_s=2.0):
        # fail-closed: resolve key from arg or os.environ["ALPHA_VANTAGE_API_KEY"]; if absent -> store None,
        #   raise DataProviderError ONLY on fetch (NOT at import/construction) so discovery never crashes.
        ...
```

Key design points (each maps to a rail / finding):

- **Endpoint:** `GET https://www.alphavantage.co/query`, params `{function: "TIME_SERIES_DAILY", symbol: asset, outputsize: self._outputsize, datatype: "json", apikey: key}`. Use `datatype=json` (CSV is fine too but JSON keeps one parse path). Default `outputsize=compact` (free-tier safe; `full` is premium and would silently rate-limit). [Finding #2]
- **Fail-closed (rail):** if `api_key` and `ALPHA_VANTAGE_API_KEY` are both unset, `fetch_bars` raises `DataProviderError("ALPHA_VANTAGE_API_KEY not set")`. Because `fetch_with_chain` treats `DataProviderError` as transient-but-fall-through, a missing key makes AV a **silent no-op fallback** (chain moves on) rather than a crash — exactly the silence-contract + default-OFF behavior we want. Do NOT raise at construction (would break entry-point discovery on daemons without a key). [Finding #4]
- **Rate-limit classification (the trap):** after `resp.json()`, BEFORE looking for `"Time Series (Daily)"`:
  - if `"Note"` in body OR (`"Information"` in body and any of {"rate limit","api key","premium"} in its lowercased value) → raise `RateLimitError(...)` (→ chain backs off + falls through). [Findings #2,#4]
  - if `"Error Message"` in body → raise `DataProviderError(...)` (bad symbol/params; transient-class so chain still tries next, but it won't retry-loop forever). Consider `DataQualityError` only if you want hard-stop; prefer `DataProviderError` so a typo'd equity still gets yfinance.
  - HTTP-level: `resp.raise_for_status()` wrapped — map `requests.HTTPError`/`ConnectionError`/`Timeout` → `DataProviderError`; a real `429` (rare from AV) → `RateLimitError`.
- **Parse:** `series = body["Time Series (Daily)"]`; build rows casting strings → float (`"1. open"`…`"4. close"`) and int (`"5. volume"`); timestamp = `pd.to_datetime(date_str)` **localized US/Eastern** (`"5. Time Zone"` is US/Eastern) then let `validate_bars` normalize to tz-naive UTC. [Finding #2]
- **`validate_bars(out)`** (from `data.base`) — reuse verbatim; gives the same NaN/zero-vol/dedupe/sort/min-2 gates as the other providers. [base.py:32]
- **Leaf-level `as_of` filter (no-lookahead rail):** after validation, if `as_of` set, drop `timestamp > as_of` — copy the exact tz-handling block from `yfinance_provider.py:265-274` (cutoff → tz-naive UTC compare). Daily bars are date-stamped, so the cutoff is conservative (a bar dated D is "as-traded close of D"; treat it like yfinance does). [yfinance_provider.py:260-274]
- **Retry (determinism-safe):** wrap the single GET in a bounded `_retry_with_backoff` clone (3 attempts, 2s/4s) that retries on `RateLimitError` + `ConnectionError`/`Timeout` only. Mirror `yfinance_provider.py:62-98`. Note: free-tier 5/min means a per-minute throttle resolves in ≤12s, so 2s/4s backoff then chain-fallthrough is the right budget; the 25/day quota will NOT resolve on retry → that's why we fall THROUGH to the next provider rather than retry-loop. [Findings #2,#5]
- **`fetch_latest(asset, timeframe, lookback=500)`** — compute `start = now - lookback*slack`, call `fetch_bars`, `.tail(lookback)`. Mirror `yfinance_provider.py:278-302`. (Free tier caps at 100 daily points regardless; document that.)
- **`health()`** — `{provider, n_fetches, n_errors, last_fetch_at, has_key: bool}` (NEVER log the key value).

## Pitfalls + rails to respect

- **Free tier 25/day is brutal.** AV is a *last-resort* fallback for equities, not a primary. A 25/day quota exhausts in one busy tick if used as primary. Order MUST be **yfinance first, AV last**, and AV should ideally only fire when yfinance is down. Document loudly; consider an optional read-through cache (the repo already has `OhlcvCache` at `data/cache.py`) keyed `alphavantage/<sym>-1d.parquet` so we don't burn quota on repeats. [Finding #2]
- **HTTP 200 ≠ success.** Must inspect the JSON body for `Note`/`Information`/`Error Message` BEFORE indexing `"Time Series (Daily)"`, or you'll `KeyError` and misclassify a throttle as a code bug. [Findings #2,#4]
- **`_ADJUSTED` is premium and has different JSON keys.** Default to raw `TIME_SERIES_DAILY` (matches yfinance `auto_adjust=False`). Mixing adjusted AV bars with raw yfinance bars in the same cache/chain would corrupt continuity. [Finding #2]
- **All AV values are strings** → explicit float/int casts; a missing cast silently makes object-dtype columns that break `validate_bars`' numeric drops. [Finding #2]
- **Timezone:** AV daily is US/Eastern dates. Localize before `validate_bars`; reuse the exact tz-naive-UTC compare block from yfinance for the `as_of` filter or you'll hit the pandas-2.x tz-aware-vs-naive `TypeError` (the comment at `yfinance_provider.py:269-272` documents this exact bug). [no-lookahead rail]
- **No-lookahead (rail):** apply the leaf-level `as_of` filter AFTER `validate_bars`, identical to yfinance/ccxt. Daily bars: a bar dated D is the close of D — admissible at `as_of >= D`. [protocol.py:508-512]
- **Determinism (rail):** output DataFrame must be a pure function of the JSON input (no `now()` in the returned bars). Health counters/`last_fetch_at` are side-channel only. The retry backoff uses `time.sleep` but does not affect output. [Finding #5]
- **Fail-closed (rail):** missing `ALPHA_VANTAGE_API_KEY` → `DataProviderError` at fetch time, never a crash at import/discovery; chain silently skips AV. Never log the key. [Finding #4]
- **Default-OFF (rail):** multi-provider chain gated behind `HERMES_QUANT_DATA_FALLBACK=1`; unset = today's single-provider path, unchanged. [B12 flag convention]
- **No circuit breaker.** Explicitly out of scope (stateful, determinism hazard, no benefit at hermes' volume). Retry+fallback is sufficient. [Finding #5]
- **Signature reconciliation risk:** changing `CcxtProvider.fetch_bars` signature touches `cli/__init__.py:1432-1439` (ccxt branch) and any test using the legacy kwargs (`tests/unit/test_ccxt_provider.py`). Keep the legacy path working (rename to `_fetch_crypto_bars`, delegate) and run the full ccxt test suite. There's also the **latent yfinance-kwargs bug at `cli/__init__.py:1450-1457`** (calls yfinance with ccxt-shaped kwargs) — surface it; fixing is cheap and removes a footgun, but is technically separable.
- **Dangling `alpaca` data-provider entry-point** in `pyproject.toml` (no `alpaca_provider.py`) — pre-existing; same class of bug as the `stacking` aggregator note. Fold a fix/removal into the same PR since we're editing that entry-point block anyway.
