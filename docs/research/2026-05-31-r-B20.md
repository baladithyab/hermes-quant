# B20 — Insider-transactions tool (Form 4) as an EvidenceRecord adapter

**Date:** 2026-05-31
**Item:** B20 — Insider-transactions tool (Form 4) as an EvidenceRecord adapter
**Verdict:** **BUILD** (read-only `filing`-kind EvidenceRecord adapter; default-OFF, fail-closed, asof-honest on **filing date / acceptance datetime**, never transaction date or now()).
**Posture:** money-software (paper). Silence-by-default, deterministic, no-lookahead.

## 1. Decisive external findings (with sources)

### 1a. yfinance insider fields — schemas confirmed LIVE (yfinance 1.4.0, probed 2026-05-31)

`yf.Ticker("AAPL")` against the installed `~/.hermes/hermes-agent/venv` returned:

**`.insider_transactions`** — `DataFrame (73, 9)`:
| column | dtype | notes |
|---|---|---|
| `Shares` | int64 | share count |
| `Value` | float64 | USD value (0.0 for gifts) |
| `URL` | object | **EMPTY STRING for every row on AAPL** — does NOT link to the SEC filing |
| `Text` | object | e.g. `"Sale at price 290.00 per share."` (free text, sometimes empty) |
| `Insider` | object | e.g. `"COOK TIMOTHY D"` |
| `Position` | object | e.g. `"Chief Financial Officer"` |
| `Transaction` | object | **EMPTY STRING for every row on AAPL** — the transaction-code column is broken |
| `Start Date` | **datetime64[ns]** | this is the **TRANSACTION date**, NOT the filing date |
| `Ownership` | object | `D` (direct) / `I` (indirect) |

**`.insider_purchases`** — `DataFrame (7, 3)`: a 6-month rollup summary, not per-event (`Insider Purchases Last 6m` / `Shares` / `Trans` with rows "Purchases", "Sales", "Net Shares Purchased (Sold)", "Total Insider Shares Held", …). Aggregate, no dates — useless as an EvidenceRecord (no published_at anchor).

**`.insider_roster_holders`** — `DataFrame (10, 7)`: current roster snapshot (`Name`, `Position`, `URL`, `Most Recent Transaction`, `Latest Transaction Date` [datetime64], `Shares Owned Directly` [int64], `Position Direct Date` [datetime64]). A *current* snapshot — inherently lookahead-unsafe for replay (it's "as of now", no filing date), and `URL` is also empty.

**The two killer problems with yfinance for this adapter:**
1. **No filing date.** yfinance gives only `Start Date` = the *transaction* date. SEC insiders have **up to 2 business days** (and historically much longer for late filings) between transacting and the filing becoming public. Anchoring `published_at`/`available_at` on the transaction date is a **lookahead violation**: the market could not see the trade until the Form 4 hit EDGAR. yfinance simply does not carry the date that matters.
2. **Broken provenance + transaction code.** `URL` and `Transaction` are empty on a flagship ticker, so we can't recover the accession number (needed for `FilingEvidence.accession_number`) nor the buy/sell code (the single most signal-rich field). yfinance scrapes Yahoo's rendered widget; these columns have been intermittently empty for years (well-documented yfinance flakiness).

### 1b. SEC EDGAR — the authoritative source, but blocked from this egress

- **`data.sec.gov/submissions/CIK##########.json`** returns `filings.recent` as columnar arrays: `accessionNumber`, `filingDate`, `reportDate`, `acceptanceDateTime`, `form`, `primaryDocument`, … Form 4 rows are `form == "4"`. CIK must be **10-digit zero-padded**. Sources: SEC Developer Resources (https://www.sec.gov/about/developer-resources), Accessing EDGAR Data (https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data).
- **`efts.sec.gov/LATEST/search-index`** — EDGAR full-text search JSON API (AWS API-Gateway → OpenSearch). Params: `q`, `forms` (matches root form, so `forms=4` covers `4` and `4/A`), `ciks` (zero-padded; the insider-subject CIK appears in `_source.ciks[]` for Form 4), `dateRange=custom&startdt=&enddt=`, `from`, `size` (max 100). Each hit `_id` embeds the accession; `_source` has `file_date`, `form`, `entity_name`. **Index coverage starts 2001-05-04 only.** Sources: efts FAQ (https://www.sec.gov/edgar/search/efts-faq.html), tldrfiling EFTS guide (https://tldrfiling.com/blog/sec-edgar-full-text-search-api), browse.sh skill capture (https://browse.sh/skills/sec.gov/search-edgar-fulltext-dpk6r2).
- **Form 4 ownership XML** (`ownershipxmltechspec`, https://www.sec.gov/info/edgar/ownershipxmltechspec-v3.pdf) carries the rich fields: header `FILED AS OF DATE` + `ACCEPTANCE-DATETIME` (when it went public), `periodOfReport` (= earliest transaction date on Form 4), per-line `transactionDate`, `transactionCode` (P/S/A/M/G/F/C/J — buy/sell/award/exercise/gift/tax/…), `transactionShares`, `transactionPricePerShare`, `acquiredDisposedCode` (A/D), `sharesOwnedFollowingTransaction`, `directOrIndirectOwnership`, `transactionTimeliness` (blank=timely, `L`=late). The SEC also publishes quarterly **Insider Transactions Data Sets** (`insider_transactions_readme.pdf`) with `FILING_DATE` AND `PERIOD_OF_REPORT` AND `TRANS_DATE` as **distinct** columns — confirming at the source-of-truth level that filing-date ≠ transaction-date and both are available from EDGAR. Sources also: sec-api.io Form-4 dataset doc (https://sec-api.io/datasets/form-4) — `filedAt` = EDGAR acceptance datetime, `periodOfReport` = date of earliest reported transaction.

- **CRITICAL ENVIRONMENT FINDING — SEC blocks this sandbox egress.** Probed live 2026-05-31 with a compliant `User-Agent`. General internet works (`https://example.com` → 200; Yahoo/yfinance → 200), but **every** SEC host returns **HTTP 403 Forbidden**:
  - `https://www.sec.gov/files/company_tickers.json` → 403
  - `https://data.sec.gov/submissions/CIK0000320193.json` → 403
  - `https://efts.sec.gov/LATEST/search-index?q=...` → 403
  - `https://www.sec.gov/cgi-bin/browse-edgar?...&output=atom` → 403

  This is the documented SEC datacenter/cloud-IP block, not a UA problem (UA was correct). SEC throttle/abuse rules: **max 10 req/s**, **mandatory `User-Agent` of the form `Sample Company Name AdminContact@example.com`** (name + contact email), exceeding it → ~10-minute IP block. Sources: SEC "new rate control limits" (https://www.sec.gov/filergroup/announcements-old/new-rate-control-limits), Accessing EDGAR Data, EFTS guide.

### 1c. Existing libraries surveyed (for "no-key adapter" friction)
- `edgartools` (https://edgartools.readthedocs.io/en/latest/guides/track-form4/) and `sec-edgar-api` (https://sec-edgar-api.readthedocs.io) both wrap data.sec.gov/efts cleanly with a UA-string constructor. Either would parse Form 4 well — but both still hit the **same SEC hosts that 403 from our egress**, and both are new heavy deps. ## 2. Repo grounding — the patterns this MUST fit

Read: `hermes_quant/evidence/schema.py`, `evidence/store.py`, `evidence/lookahead_gate.py`, `evidence/__init__.py`, `catalyst/ingest.py`, `catalyst/social.py`, `data/yfinance_provider.py`, `catalyst/__init__.py`.

- **`FilingEvidence` already exists and is the exact target** (`evidence/schema.py:160-163`): a `filing`-kind `EvidenceRecord` subtype with `accession_number: str` and `form_type: str` and the docstring literally names `'4'` as an example form. **It is currently produced NOWHERE in the codebase** (`grep` for `FilingEvidence`/`accession` outside schema/init = 0 hits). B20 is the first producer of `FilingEvidence`. This is a clean greenfield slot that the schema was pre-designed for.
- **EvidenceRecord invariants** (`schema.py`): frozen + `extra="forbid"`; three tz-aware timestamps `published_at` ≤ `available_at` (causality enforced at construction, raises `EvidenceCausalityError`); `id == derive_evidence_id(kind, source, payload_hash)` (deterministic UUID5 → write-time dedup); `payload_hash` via `sha256_of_json` (canonical sorted-keys). `INGEST_LAG_FLOOR_SECONDS["filing"] = 0` (use `compute_available_at("filing", published_at)` → `available_at == published_at`).
- **The asof anchor is load-bearing.** Both ingesters (`catalyst/ingest.py:33`, `catalyst/social.py`) repeat the same rule: `published_at` = the *real observation/publication* timestamp; **an item without a parseable timestamp is SKIPPED, never defaulted to `now()`** (`ingest.py:127`, `social.py:86`). For Form 4 the publication time = **EDGAR acceptance datetime / filing date**, NOT the transaction date.
- **Stdlib-only ingester convention.** `catalyst/ingest.py` and `catalyst/social.py` use `urllib.request` + `xml.etree.ElementTree` + `email.utils.parsedate_to_datetime` — **no feedparser, no requests**. They take an **injectable `fetcher(url, timeout) -> bytes`** so tests are offline-deterministic, and a descriptive `User-Agent` is sent. New adapter must follow this exactly (only `json`/`xml.etree` parsing needed for EDGAR).
- **Silence-by-default / fail-closed.** Every fetch is wrapped `except Exception: logger.warning(...); return [], latency` — "a dead feed must not break the daily run" (`ingest.py:154`, `social.py:160`). Adapter returns `[]` on ANY error (403, timeout, parse failure, empty).
- **Default-OFF flag convention.** `catalyst/__init__.py:18` documents `HERMES_QUANT_SEMANTIC_ENABLED`; `eval.py` reads `HERMES_QUANT_CONVERGENCE` at call-time. New flag: `HERMES_QUANT_INSIDER_ENABLED` (read at call time; OFF → adapter returns `[]`). `.env` is tool-guarded; the agent emits the flag line, the operator enables it.
- **Store + lookahead gate are decoupled & ready.** `EvidenceStore.append(record)` is idempotent on `id`, partitions by `available_at` year/month/kind, append-only (`overwrite_partition` always raises). `lookahead_gate.check_view_lookahead` only needs `store.get(id)['available_at']` — so once a `FilingEvidence` is stored with an honest `available_at`, any analyst citing it is auto-protected by the existing CI gate.
- **Tool layer is read-only by ADR-0007** (`tools.py:1-8`): tools surface state, never spawn/mutate/trade; heavy imports lazy-loaded; handlers return JSON-string dicts. A `quant_insider` read tool fits here.

## 3. Recommended implementation for THIS repo

**Source decision: SEC EDGAR is the only asof-honest source; yfinance is NOT acceptable as the primary because it lacks the filing date and has broken URL/transaction-code columns.** Build a stdlib EDGAR adapter that mirrors the `catalyst/ingest.py` shape. yfinance MAY be a *clearly-labeled, lookahead-quarantined* enrichment fallback only (see pitfalls) — not the EvidenceRecord anchor.

### File: `hermes_quant/evidence/adapters/form4.py` (new; new `adapters/` package under evidence)
Stdlib-only (`urllib.request`, `json`, `xml.etree.ElementTree`, `email.utils.parsedate_to_datetime`, `datetime`, `hashlib` via schema helpers). Pattern copied from `catalyst/ingest.py`:

```
_UA = "HermesQuant/0.1 research <contact-email>"   # SEC-mandated name+email form
_SUBMISSIONS = "https://data.sec.gov/submissions/CIK{cik10}.json"
_FORM4_XML   = "https://www.sec.gov/Archives/edgar/data/{cik}/{accno_nodash}/{primary_doc}"
_TICKERS     = "https://www.sec.gov/files/company_tickers.json"  # ticker -> CIK map (cache to ~/.hermes/quant/)

@dataclass(frozen=True)
class InsiderFiling:                  # the normalized intermediate (mirrors CatalystItem)
    accession_number: str
    form_type: str                    # "4" or "4/A"
    issuer_symbol: str
    issuer_cik: str
    filed_at: datetime                # tz-aware UTC — ACCEPTANCE datetime; THE asof anchor
    period_of_report: date            # transaction/event date (metadata only, NOT the anchor)
    primary_doc: str
    # optional parsed line items (transactionCode, shares, price, A/D, D/I) when XML fetched

def _fetch_raw(url, timeout) -> bytes: ...        # urllib + _UA, injectable
def resolve_cik(symbol, *, fetcher=None) -> str | None       # ticker -> 10-digit CIK
def fetch_form4_filings(symbol, *, since=None, fetcher=None, timeout=15.0) -> tuple[list[InsiderFiling], float]
    # 1. resolve CIK; 2. GET submissions JSON; 3. zip the columnar recent arrays;
    # 4. keep form in {"4","4/A"}; 5. parse acceptanceDateTime -> tz-aware UTC (filed_at);
    #    if unparseable -> SKIP (never now()); 6. optional date filter on filed_at >= since.
    # Never raises: any failure -> ([], latency). 403 from SEC -> [] (logged).

def to_filing_evidence(f: InsiderFiling) -> FilingEvidence:
    payload = {... canonical dict of the filing + line items ...}
    phash = sha256_of_json(payload)
    published = f.filed_at                                   # honest: acceptance datetime
    available = compute_available_at("filing", published)    # +0s
    return FilingEvidence(
        id=derive_evidence_id("filing", "sec_edgar_form4", phash),
        kind="filing", symbol=f.issuer_symbol, source="sec_edgar_form4",
        published_at=published, ingested_at=<now-utc>, available_at=available,
        payload_ref=f"https://www.sec.gov/Archives/edgar/data/{f.issuer_cik}/...",
        payload_hash=phash, accession_number=f.accession_number, form_type=f.form_type,
    )
```

Key correctness rules baked in:
- `published_at = acceptanceDateTime` (UTC). EDGAR gives `2025-03-15T16:30:00-04:00`; convert to UTC. If only `filingDate` (date) is available, use end-of-day-ET → UTC as a conservative (later) anchor so we never claim it was public earlier than it was. **Never** use `periodOfReport`/`transactionDate` as the anchor.
- `ingested_at = datetime.now(timezone.utc)` is fine (it's the only one that legitimately may be wall-clock; causality only constrains `available_at ≥ published_at`).
- Same-payload re-fetch → same `payload_hash` → same `id` → `store.append` is a no-op (idempotent).

## 5. Pitfalls + rails to respect

- **NO-LOOKAHEAD (the #1 trap):** anchor `published_at` on the **EDGAR acceptance datetime / filing date**, NEVER on `transactionDate`/`periodOfReport`/`Start Date`. Insiders file up to 2 business days late (often more historically) — using the trade date back-dates public availability and corrupts every backtest that cites the record. This is exactly why **yfinance is disqualified as the anchor** (it only has the trade date). An item with no parseable filing/acceptance timestamp → **SKIP** (never `now()`).
- **DETERMINISM:** identity via `derive_evidence_id(kind, source, payload_hash)` over a canonical `sha256_of_json` payload; same filing → same UUID → idempotent append. Build the payload dict deterministically (sorted, no `now()` inside the hashed payload — `ingested_at` is outside the identity triple).
- **SILENCE-CONTRACT / FAIL-CLOSED:** every network/parse path wrapped → return `[]`. The SEC 403 from our egress is a *normal expected outcome here*, not an exception to surface; the adapter must emit zero filings quietly and log a warning. A dead/blocked feed must not break the run or fabricate data.
- **DEFAULT-OFF:** `HERMES_QUANT_INSIDER_ENABLED` read at call time; OFF ⇒ `[]`. Enable only after connectivity smoke + negative-control eval. `.env` is tool-guarded — agent emits the line, operator flips it.
- **READ-ONLY (ADR-0007):** the `quant_insider` tool only reads/surfaces; it must not place trades or mutate state. Adapter only fetches + writes append-only EvidenceRecords.
- **Rate-limit hygiene:** ≤10 req/s; add an inter-call sleep like `yfinance_provider`'s 100ms and the `_retry_with_backoff` pattern for transient 429/timeout (but a 403 IP-block is NOT retryable — back off long, don't hammer).
- **Amendments & restatements:** `4/A` supersedes `4` for the same event. Use `EvidenceRecord.supersedes` to link the amendment to the original rather than silently overwriting (store is append-only and will raise on overwrite).
- **yfinance-as-fallback hazard:** if yfinance is ever wired as an enrichment, its rows must be tagged `source="yfinance_insider"` and either (a) NOT emitted as EvidenceRecords at all, or (b) emitted with `available_at` forced to a conservative LATE bound and flagged lookahead-unsafe — because yfinance gives no filing date and empty URL/transaction-code. Default: do not emit yfinance rows as evidence.
- **EFTS coverage floor:** full-text search only indexes since 2001-05-04; `submissions` JSON `recent` block is the last ~1000 filings — older Form 4s live in `filings.files[]` overflow shards. Handle the overflow when a deep history is needed.

## 6. Scope verdict

**BUILD.** Rationale: B20 is not a research-then-decide item (B23/B24/B29) — it is a concrete adapter, and the repo was *pre-architected* for it: `FilingEvidence(form_type, accession_number)` exists in the schema, names `'4'` explicitly, and has **no producer yet**. The lookahead gate, append-only store, and stdlib-ingester pattern are all in place and directly reusable. The external research yields a clean, defensible design: **SEC EDGAR is the only asof-honest source** (carries filing date + acceptance datetime separate from transaction date), **yfinance is disqualified as the anchor** (no filing date; empty URL/transaction-code columns confirmed live on AAPL). The one real risk — SEC 403s from cloud egress (confirmed live from this sandbox) — is fully absorbed by the existing fail-closed/silence contract (adapter returns `[]`), so it gates *enablement*, not *building*. Build default-OFF; enable behind a connectivity smoke check + negative-control eval, exactly as the catalyst subsystem was rolled out.
