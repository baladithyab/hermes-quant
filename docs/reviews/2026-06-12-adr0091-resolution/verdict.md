## Rationale

C is the only option that satisfies all four binding money-software principles at once, and I verified its central premise against the live tree. Principle (1) immutable-log: B's chosen Decision-Outcome step 3 (ADR-0091 lines 194-203) rewrites executions.jsonl in place — even backed-up, this is a mutation of the ADR-0085 authoritative append-only source of truth, and if the recompute mis-orders or mis-buckets, the corruption is baked into the source where reconcile reports 0 divergence (the precise silent mode that hid this bug). C changes interpretation only; bytes are inviolate; legacy records (no schema_version) read as absolute-target, which is what they already are. Principle (2) no producer read-modify-write race: B's producer must read reconstruct_portfolio_state at fill time and append the difference; I confirmed paper.py's existing position read (cap-clip lines 438-450) sits OUTSIDE the append_locked block (line 291), so read-compute-append is non-atomic and concurrent fires can append inflation into the immutable log. C does its read at FOLD time over the already-persisted ordered stream — zero new producer read. Principle (3) BOTH consumers correct: I confirmed both state.db folds (portfolio_state.py _replay_record:984/998 and _apply_execution_unsafe:523/607) and the settlement FIFO (settlement_loop.py _normalize_exec_record:524-536, join_exit_fills:706-722) already make the IDENTICAL interpretation that the signed size field is a per-fill delta — settlement_loop.py:489-499 literally cites portfolio_state's pos_delta convention by name. A single running-net normalizer therefore satisfies both, and the resulting signed delta flows through each consumer's UNCHANGED algebra. Principle (4) ADR-0011 preserved / no cost-basis corruption: C feeds a TRUE signed delta into the unchanged _update_position (lines 929-951): a genuine ADD blends avg at 937-941; a re-affirmation yields delta 0 and the same_direction branch returns old_avg unchanged. This is the structural difference from rejected-A, which SET qty and overwrote avg. The det-equity AAPL-12x case folds via reactor_metadata.quantity (line 385 filled_qty -> leg_quantity branch), so the normalizer must carry-forward the quantity path too — confirmed and scoped into Increment 0. B scores high on both-consumers but is floored on log-integrity by a confirmed immutable-log P0 and a confirmed producer-race P0; C carries neither.

## Adversarial P0-hunt against the winner

I tried hard to break C against the actual code and found three attack vectors; the third is the genuine residual that Increment 0 must close structurally. (1) ORDERING-DIVERGENCE attack: delta = target − carried_forward_net is ORDER-DEPENDENT. The settlement FIFO does NOT fold in arrival order — join_exit_fills sorts asof-honest with an _idx tie-break (settlement_loop.py:672 `sorted(indexed, key=_exec_sort_key)`, key at 587-605), while state.db _replay_record walks the file in bus/append order. If the shared normalizer is run as a pre-pass over a DIFFERENTLY-ordered stream for each consumer, the same records produce different per-fill deltas in the two paths at same-asof ties — re-introducing the two-divergent-views P0 (#4) through the back door. This is REAL, not theoretical: the FIFO's own defect-(2) comment (lines 593-599) documents that ordering inverts side+magnitude. Mitigation exists (normalizer must define ONE canonical per-bucket ordering and BOTH consumers must honor it; for the FIFO the carry-forward must run on the asof-honest-sorted stream the matcher actually consumes, not raw bus order) — so it is closable, but only by mandate, not by convention. (2) INCREMENTAL-vs-REBUILD attack: state.db has TWO folds — the full rebuild _replay_record (line 954, running_net in memory) and the live incremental _apply_execution_unsafe (line 607, which reads the persisted positions row at 594-606 per fill). A normalizer carrying running_net in memory matches the rebuild but the incremental path must seed running_net from the persisted position or the two state.db folds diverge from each other (a single-consumer internal split, still a divergence). Closable by driving the incremental path with state.db as the carry-forward source, but it is the highest-risk implementation detail. (3) FLIP-SPLIT attack (the subtlest): on a genuine flip (e.g. +5% target then −5% target, net delta −10%), the normalizer emits ONE signed delta of −0.10. state.db _update_position handles that single delta natively (flip branch line 942-945, new_avg=fill_price). But the FIFO close loop (728-776) consumes the −10% as a single opposing fill that closes the +5% lot (5% matched) and opens a 5% residual lot in the new direction (line 802-806) — correct ONLY because the queue fully drains. If instead the carry-forward had a stale net (e.g. mis-seeded after a deferred-exit at 800), the FIFO would DEFER rather than flip, leaving realized P&L unsettled. I could NOT produce an unmitigated break: in all three the failure requires the normalizer to be implemented as two independent carry-forwards or with inconsistent ordering — exactly what Increment 0 forbids. C's no-P0 status is genuinely CONTINGENT on the single-shared-normalizer-with-one-canonical-ordering mandate being a hard architectural gate.

**Winner survives:** True
