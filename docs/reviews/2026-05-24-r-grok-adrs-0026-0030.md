# Reviewer: Grok-4.3 — Decisive critique of ADR-0026..0030

## P0 (BLOCKER — won’t accept this ADR as written)
**ADR-0029 D7**: The 60-day paper-only gate is theater, not engineering. "60 days of evidence" is a calendar proxy, not a statistical one. With ~5 trades/week expected, you're promoting on n≈40 with no minimum sample-size requirement for the risk-gate calibration, no minimum number of gamma-spike or pin-risk events observed, and no explicit cross-validation against the synthetic baseline. Replace with: minimum 120 calendar days **and** ≥80 settled multi-leg outcomes **and** zero breaches of the immutable rules (silence-by-default, BPR buffer, no-naked) during the window. The current gate is a rounding error away from live authorization of an under-tested reactor.

**ADR-0030 D1**: The three-namespace DSL is deliberately crippled. `fundamentals`/`options_chain`/`event_flags` cannot express liquidity-floor interactions with earnings guards, regime-conditional IV-rank floors, or bid-ask × volume filters. This forces house-default overrides in stage 5 of the pipeline and guarantees every non-trivial methodology will eventually need a Python subclass. Add a fourth namespace (`risk_liquidity`) now; deferring it guarantees the DSL becomes shelfware the moment the first real reel lands.

## P1 (must-fix-before-impl)
**ADR-0026 D2/D6**: The Bull/Bear/Synthesizer cron is the single point of failure that bricks the entire learning surface. If the cross-family model-roster ever returns fewer than three families, the audit aborts with zero signal. Couple this with the $30/mo hard cap in D7 and you have a system that silently starves itself when Claude pricing spikes. Fix: make family diversity a soft requirement with a deterministic fallback to "Bear + Synthesizer only" that still produces a report (marked LOW_CONFIDENCE), and drop the cap to $8/mo. The actual spend is ~$1.40; $30 is permission to waste.

**ADR-0027 D3/D5**: Capital-at-risk sizing is correct, but the gamma-spike kill-switch (2× gamma_cap) fires from settlement_loop on every tick with no cooldown or hysteresis. A single bad options snapshot that momentarily inflates gamma will install a durable halt across the entire account. Add a 5-tick persistence requirement and an explicit "gamma_spike_event" postmortem field so the retro loop can actually learn from these events instead of just accumulating halts.

## P2 (nits)
- ADR-0028 D3: py_vollib early-exercise caveat is flagged but the `iv_source` enum has no `computed_european_approximation` value. Add it.
- ADR-0030 D7: The 3:30 PM refresh cron is underspecified; it should also re-run the methodology loader to catch YAML edits without daemon restart.

## Strengths
- ADR-0026's two-layer deterministic + adversarial LLM is the right shape; single-layer would be confirmation-biased noise. The immutables preamble + defense-in-depth re-check is the correct constitutional design.
- ADR-0027 correctly refuses delta-equivalent sizing and makes BPR the binding constraint. The per-strategy hard-rule table is the clearest expression of "hard rules > learned policy" in the entire bundle.
- ADR-0029's atomic mleg + next-day NTA reconciliation is the only honest way to handle paper settlement delay.

## Verdict (committed: ACCEPT-WITH-FIXES)
The five ADRs are a coherent v0.5.0 plan provided the P0 blockers are resolved before any code lands. The retro loop (0026) is non-negotiable for long-term survival; without it the other four are just more code that will never be questioned. The decisive failure mode is not a bad options trade — it is the retro loop being starved, gamed, or silently bypassed because the cost cap and family diversity invariants were treated as soft.
