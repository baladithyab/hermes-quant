### Convergent P0s

#### CP0-1: ADR-0029 D7 paper→live gate is structurally weak

**Reviewers:** Gemini (calls it a race condition + config-drift hazard) + Grok (calls it calendar-proxy theater not statistical evidence).

**Same defect, two angles:**
- Gemini: `account.is_paper is False` boolean is racy; staging environment misconfiguration could trip it.
- Grok: 60 calendar days with ~5 trades/week ≈ n=40 outcomes, not enough for any of the gate's risk-relevant events (gamma-spikes, pin-risk, BPR breaches) to have been observed.

**Synthesis fix (combines both):**
1. Replace `is_paper` boolean check with type-level prevention. The `LiveBroker` class shall not have a `submit_mleg_order` method until a future ADR-00XX explicitly adds it. `PaperBroker` is the only class with this method until then. (Gemini's recommendation, structural rather than runtime.)
2. Replace "60 days" with: ≥120 calendar days **AND** ≥80 settled multi-leg outcomes **AND** zero immutable-rule breaches (silence-by-default, BPR buffer 25%, no-naked) during the window **AND** the 3-of-3 calibrator targets within ±5% of the realized rate over the same window. (Grok's recommendation, statistical.)
3. The promotion ADR (ADR-00XX, future) MUST reference ADR-0026 weekly retro outputs as evidence — i.e., the retro loop's monthly meta-retro output must include a "promotion-readiness" field that the gate can read.

#### CP0-2: ADR-0026 retro-loop cost ceiling math is fragile

**Reviewers:** Gemini (P2: monthly meta-retro context window will balloon) + Grok (P1: $30/mo is permission-to-waste; actual is ~$1.40, drop to $8/mo as forcing function).

**Same defect, different stakes:** Gemini says "the math is wrong"; Grok says "the budget is too generous." Both are correct.

**Synthesis fix:**
1. Restate ADR-0026 D7 cost arithmetic with explicit per-trade-volume sensitivity (per DeepSeek P2-1, the claim of cost-independence from trade count is false).
2. Reduce hard cap from $30/mo to $8/mo. Document this is a forcing function — the retro loop should be cheap or it's wrong.
3. Add a soft-fallback: when the model-roster has fewer than 3 families available, audit runs as "Bear + Synthesizer only" with `LOW_CONFIDENCE` flag (per Grok). Better a flagged audit than no audit.
4. Add explicit context-window monitoring: if the monthly meta-retro prompt exceeds 200KB, rotate to a sliding-window summary of older weeks rather than full text (per Gemini P2).

### Solo P0s (sanity-checked, all stand)

#### P0-3: ADR-0027 D3 covered_call denominator missing `×100` (DeepSeek)

**Sanity check:** Read ADR-0027 D3 directly. The CSP case has `collateral = strike × 100` explicit. The CC case has "current basis of long stock" without the `×100`. **DeepSeek is right** — implementations following the ADR literally would produce 100× over-counted CC contracts. The corrected formula needs to distinguish initiation vs. wheel-overlay (wheel-overlay has the capital already deployed in the underlying, so sizes against `call_mid × 100` not the stock basis).

**Action:** Patch ADR-0027 D3 with the corrected formula DeepSeek proposed.

#### P0-4: ADR-0027 D6 net-Greeks drops stock leg of covered call (DeepSeek)

**Sanity check:** Read ADR-0027 D6. `aggregate_legs(legs: list[OptionLeg])` iterates only `OptionLeg` objects. A covered call has `(long stock, short call)` — the stock leg is not an `OptionLeg`. **DeepSeek is right** — the function will silently drop the stock's +100 delta.

**Action:** Patch ADR-0027 D6 to either (a) define `Leg` as a Union of `OptionLeg | StockLeg`, or (b) add an explicit `underlying_stock_position` field to `MultiLegProposal` and aggregate it into net-greeks separately.

#### P0-5: ADR-0028 D5/D7 parquet replay bypasses greek recomputation (DeepSeek)

**Sanity check:** Read ADR-0028 D5 and D7 together. D5 mandates `as_of` semantics + `shuffle_timestamps_test` CI gate. D7 records every `fetch_chain` to parquet. The replay path reads the parquet greeks directly. **DeepSeek is right** — if the parquet writer accidentally records greeks computed from `as_of=T` chain but `iv` from `as_of>T` market data, replay serves contaminated greeks and the CI gate (which re-computes greeks from bars ≤ T) never catches it.

**Action:** Patch ADR-0028 D7 to require either:
1. Replay re-runs `complete_greeks` against parquet's stored `(spot, strike, dte, iv)` inputs at replay time, with `as_of`-filtered market data only, OR
2. Parquet records `greeks_computed_at` provenance field; replay verifies `greeks_computed_at ≤ as_of` strictly.

#### P0-6: ADR-0026 D5 `code_change` scope is arbitrary code execution (Gemini)

**Sanity check:** Read ADR-0026 D5. Yes, `scope_type` includes `code_change` which permits the LLM to emit a unified diff that the human reviews via `$EDITOR` and applies via `git apply`. **Gemini is right** — even with human review, complex diffs are prone to silent rule violations being missed. The whole point of "hard rules > learned policy" is the rules are encoded in code, not in policies the LLM can mutate via diffs.

**Action:** Patch ADR-0026 D4/D5 to remove `code_change` from `scope_type`. Allowed scopes restrict to: parameter tuning (numeric value within already-codified bounds), analyst weight adjustment (within ADR-0023's reweighting machinery), risk-gate threshold adjustment (within ADR-0027's per-strategy bounds — never below the immutable absolute floor), recipe-YAML edit (validated by ADR-0030's schema). Anything requiring a code change escapes the retro loop and goes through normal ADR/PR process.

#### P0-7: ADR-0026 D1 counterfactual `was_gate_rejection_correct` non-determinism (Gemini)

**Sanity check:** Read ADR-0026 D1. The would-be hold window for a gate-rejected trade is computed from realized bars. **Gemini is right** — without tick-level data, intra-bar fill assumptions (worst-case-open vs. mid-bar vs. close) are heuristic, and the heuristic is not specified.

**Action:** Patch ADR-0026 D1 to explicitly define the counterfactual execution heuristic: "Assume worst-case fill: long entries fill at bar high, exits fill at bar low. This produces a conservative `was_gate_rejection_correct` — false negatives (gate was right to reject) become more likely than false positives (gate was wrong)." Add a corresponding test asserting the heuristic is deterministic given the same input bars.

#### P0-8: ADR-0030 D1 DSL needs 4th namespace `risk_liquidity` (Grok)

**Sanity check:** Read ADR-0030 D1. Three namespaces (`fundamentals`, `options_chain`, `event_flags`). What's missing: bid-ask spread × volume × open-interest × earnings-window — these cross multiple namespaces (option-level liquidity + fundamental-level event timing + chain-level spread). Forcing them into one of the three existing namespaces breaks the namespace abstraction. **Grok is right** — the methodology library will need a 4th namespace within weeks of first reel ingestion.

**Action:** Patch ADR-0030 D1 to add `risk_liquidity` as the fourth namespace. Move bid/ask, spread, volume, OI rules into it. Document the namespace as "the always-on quality floor every methodology must clear, regardless of what filters the methodology specifies."

## Convergent strengths (DO NOT change)

All 3 reviewers independently flagged these as the bundle's strongest features:

1. **Atomic HITL approval at the type level** (ADR-0029 D6) — making partial leg approval unrepresentable in the schema is correctness-by-construction. (DeepSeek + Gemini)
2. **Bull/Bear/Synthesizer adversarial scatter with cross-family enforcement** (ADR-0026 D2) — the strongest defense against confirmation bias. (DeepSeek + Grok)
3. **Immutable `evidence_postmortem_ids` link** (ADR-0026 D4) — the audit trail can't be rewritten retroactively. (DeepSeek + Gemini)
4. **From-reel dual-branch extraction with diff** (ADR-0030 D3) — defense against single-model extraction errors. (DeepSeek)
5. **Per-strategy hard-rule table for risk gate** (ADR-0027) — clearest expression of "hard rules > learned policy" in the bundle. (Grok)
